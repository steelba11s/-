# C sharp и платформа dot NET с нуля
## Язык платформа и интерфейс
C# читается «си шарп». Это язык, на котором мы описываем действия программы: прочитать текст, сравнить символы, обработать нажатие кнопки, сохранить файл. Код в файле .cs — обычный текст с правилами записи. Компьютеру нужно перевести его в выполняемую форму.
.NET читается «дот нет». Это платформа: среда выполнения и большой набор готовых средств для работы со строками, файлами, временем и коллекциями. C# — язык инструкций, .NET — средства для их выполнения. Avalonia — библиотека для построения окон и элементов интерфейса поверх .NET. Это три связанные, но разные вещи.
Представь мастерскую. C# — язык, на котором написано задание мастеру. .NET — оборудование и общие инструменты. Avalonia — набор деталей для панели управления: окна, кнопки, поля ввода. Проект приложения соединяет всё это и добавляет собственные правила работы.
SDK — набор для разработчика. В нём есть инструменты сборки, компилятор и средства запуска. Runtime — среда выполнения готового приложения. Для изменения и сборки нужен SDK. У готовой самостоятельной сборки необходимые компоненты .NET могут лежать рядом с приложением.
NuGet — система получения библиотек. PackageReference в .csproj указывает имя и версию готового пакета. ProjectReference связывает проекты внутри решения. Например, приложение использует классы своего Core через ProjectReference. Это не копирование текста исходников вручную.
## Как исходники становятся работающей программой
Обычная последовательность такая: исходники C# и разметка Avalonia → сборка проекта → файлы приложения → запуск среды .NET → создание окна → ожидание действий пользователя. В обычной сборке C# сначала получается промежуточный код IL; среда выполнения может преобразовывать его в машинный код через JIT. Для объяснения этих проектов достаточно знать этот путь; отдельная AOT-сборка здесь не показана в настройках проектов.
Программа с окном не читает весь код сверху вниз заново после каждого клика. При запуске она создаёт объекты и подписывает обработчики на события. Затем работает цикл обработки событий: нажали кнопку — вызван соответствующий метод; изменили текст — вызван другой метод.
Файлы .csproj описывают отдельные проекты. Решение .slnx объединяет несколько проектов для удобной работы. Каталог bin содержит результаты сборки, obj — промежуточные файлы. Править поведение приложения следует в исходниках, а не в сгенерированных файлах этих каталогов.
## Переменная и тип данных
Переменная — именованное место для значения. Тип отвечает на вопрос «какие значения здесь допустимы и какие операции с ними можно выполнять». Имя отвечает на вопрос «зачем это значение понадобилось».
```csharp
int errors = 2;
double accuracy = 97.5;
bool isActive = true;
string text = "Привет";
char letter = 'П';
```
int хранит целое число; double — число с дробной частью; bool — true или false; string — строку; char — одну кодовую единицу UTF-16. В обычном русском и английском тексте отдельная буква обычно занимает один char. Однако эмодзи и некоторые сложные символы могут занимать несколько единиц: String.Length не является универсальным счётчиком видимых знаков.
Знак = присваивает значение. Знак == сравнивает два значения. Поэтому errors = 2 означает «записать 2», а errors == 2 — «проверить, равно ли значение двум». Точка с запятой завершает многие инструкции. Строки пишутся в двойных кавычках, отдельные char — в одинарных.
```csharp
var count = 10;
var caption = "Готово";
```
var не означает «любой тип». Компилятор выводит тип из правой части: count будет int, caption — string. После этого нельзя просто записать строку в count. Такой вывод типа сокращает запись, сохраняя проверку типов.
## Условия циклы и индексы
```csharp
if (errors == 0)
{
    return "Без ошибок";
}
return "Есть ошибки";
```
Это учебный фрагмент тела метода, возвращающего string. if означает «если». Условие в круглых скобках должно дать bool. Фигурные скобки объединяют инструкции. return возвращает результат и сразу прекращает текущий вызов метода. В методе void можно написать просто return, чтобы выйти без значения.
```csharp
for (var i = 0; i < text.Length; i++)
{
    var symbol = text[i];
}
```
for повторяет действия. i = 0 — старт; i < text.Length — условие продолжения; i++ — увеличение на единицу после прохода. Индексы начинаются с нуля: в строке «кот» text[0] — «к», text[1] — «о», text[2] — «т». Обращение за пределы строки вызывает ошибку. foreach перебирает готовые элементы коллекции без ручного управления индексом.
Частые операторы: != — не равно; !flag — противоположное логическое значение; && — одновременно выполнены оба условия; || — выполнено хотя бы одно. В выражении a && b правая часть не вычисляется, если a уже false. Тернарная запись condition ? yes : no выбирает одно из двух значений.
## Класс объект поле и свойство
Класс — описание устройства определённой сущности. Объект — конкретный экземпляр такого класса в памяти. Один класс настроек позволяет создать несколько объектов с разными настройками. new создаёт экземпляр, а конструктор задаёт его начальное состояние.
```csharp
public sealed class TrainerSettings
{
    public float FontSize { get; set; } = 16f;
    public bool ShowKeyboard { get; set; } = true;
}
```
Это фрагмент реального класса тренажёра. class объявляет класс. public делает его доступным другим частям программы. sealed запрещает создавать классы-наследники от него. FontSize и ShowKeyboard — свойства. get разрешает чтение, set — изменение. = 16f задаёт начальное значение float; суффикс f уточняет тип числа. У свойства bool без явного начального значения исходное значение false.
```csharp
var settings = new TrainerSettings();
settings.FontSize = 24;
```
Первая строка создаёт объект. Вторая меняет его свойство. Точка означает обращение к члену объекта. Поле хранит данные непосредственно внутри класса; свойство предоставляет доступ к данным и при необходимости выполняет дополнительную логику. Поэтому свойство может не хранить отдельное значение, а вычислять его при чтении.
```csharp
public bool IsDirty => text != savedText;
```
Это учебное вычисляемое свойство: «есть несохранённые изменения, если текущий текст отличается от сохранённого». => здесь сокращает запись тела свойства. У свойства нет set: присвоить ему true вручную нельзя. Нужно изменить text или savedText, и результат сравнения изменится.
private разрешает обращаться к члену только внутри содержащего типа. public открывает доступ извне. internal ограничивает доступ сборкой. readonly запрещает переприсваивать поле после допустимой инициализации; но если поле содержит список, это само по себе не запрещает добавлять элементы в список. const задаёт константу времени компиляции.
## Метод и конструктор
Метод — именованное действие. Параметры — входные данные, возвращаемое значение — результат. Вызов session.Start(text, true) означает «попросить объект session начать попытку с данным текстом и учётом регистра». Тип void означает, что метод не возвращает значение.
```csharp
public void Reset()
{
    IsActive = false;
    IsComplete = false;
}
```
Это сокращённый учебный фрагмент сброса состояния. Reset — имя метода, пустые круглые скобки означают отсутствие параметров. В настоящем методе тренажёра также очищаются строки и время. Конструктор носит имя класса, не имеет типа возвращаемого значения и вызывается при new.
В коде встречается современная запись конструктора прямо возле имени класса: TypingSession(TimeProvider? timeProvider = null). Это первичный конструктор. Параметр со значением по умолчанию разрешено не передавать. Он нужен для выбора источника времени, в том числе тестового.
## Наследование интерфейсы и основы ООП
ООП — способ организовать программу вокруг объектов, их данных и действий. На защите полезно объяснить три идеи на конкретных примерах. Инкапсуляция: внутреннее состояние меняется через методы и свойства с контролируемым доступом. Наследование: MainWindow : Window расширяет готовое окно Avalonia. Полиморфизм: код может работать с разными реализациями одного интерфейса через общий договор.
Интерфейс перечисляет возможности, которые обязан предоставить объект. IAppDialogs описывает выбор файла и вопросы пользователю. Настоящий AppDialogs показывает окна, а FakeDialogs в тестах заранее возвращает ответы. ViewModel обращается к договору IAppDialogs, поэтому его легче проверять без ручных кликов.
Композиция означает, что объект содержит другие объекты: MainWindow хранит TypingSession или ViewModel. Здесь обычно не нужно наследовать окно от «сессии»; окно использует сессию. Это хороший пример выбора отношения «имеет» вместо отношения «является».
override заменяет разрешённую виртуальную реализацию базового класса. Например, App переопределяет Initialize. base обращается к базовой реализации. partial означает, что определение класса разделено на части, в том числе исходную и сгенерированную из разметки.
## Коллекции и LINQ
List<T> — изменяемый список элементов типа T. List<TypingSessionStats> хранит результаты попыток. Dictionary<TKey, TValue> сопоставляет ключу значение: Dictionary<char, Border> позволяет найти изображение клавиши по символу. Здесь Dictionary — структура данных C#, а WordDictionary — собственный класс приложения, несмотря на похожие названия.
IReadOnlyList<T> предоставляет чтение списка через данный интерфейс. Queue<T> — очередь: первый добавленный элемент извлекается первым. Она используется при обходе папок. Запись [] в подходящем контексте создаёт пустую коллекцию. Угловые скобки задают параметр типа; это называется обобщением, или generics.
LINQ — набор операций над последовательностями. Where отбирает элементы, Select преобразует каждый элемент, OrderByDescending сортирует по убыванию, Take оставляет первые N, ToList материализует результат в список. Max находит максимум, Average — среднее, GroupBy собирает элементы в группы.
```csharp
statistics.OrderByDescending(item => item.Date)
          .Take(500)
          .ToList();
```
Это цепочка из тренажёра. Сначала самые новые результаты оказываются впереди, затем сохраняются только первые 500, затем получается отдельный список. item => item.Date — лямбда: маленькая функция «для данного элемента взять его дату». => может обозначать лямбду или краткое тело члена класса; смысл определяется контекстом.
## Пустое значение и короткие записи
null означает отсутствие объекта или значения ссылки. Пустая строка "" существует и имеет длину ноль; null означает, что строки нет. string? показывает, что отсутствие допустимо. Настройка Nullable в .csproj помогает компилятору предупреждать об опасных обращениях.
InputBox.Text ?? "" читается «взять Text, а если там null, использовать пустую строку». Выражение document?.Path читает Path только при наличии document, иначе даёт null. Знак ! после выражения, например Inlines!, подавляет предупреждение компилятора о null, но не создаёт объект и не защищает во время выполнения.
is проверяет тип или шаблон. is not WordDictionary text означает «если значение не удалось распознать как WordDictionary и получить переменную text». switch выбирает ветку по значению или типу. nameof(IsDirty) даёт строку с именем члена; при переименовании инструменты могут обновить ссылку безопаснее, чем обычный текст в кавычках.
$"Ошибок: {errors}" вставляет значение в строку. Формат :F1 показывает одну цифру после десятичного разделителя, :F0 — число без дробной части. Это меняет отображение, а не сам расчёт. \n в строке означает перевод строки. // начинает комментарий для человека.
## События асинхронность и освобождение ресурсов
Событие — уведомление о том, что что-то произошло. Обработчик — код, который реагирует. Запись button.Click += ... подписывает обработчик; -= снимает подписку. Подписка не нажимает кнопку немедленно. В выражении (_, _) => StartSession() параметры события не используются, а после события вызывается StartSession.
async и await позволяют описать ожидание операции без блокирующего ожидания потока в точке незавершённого await. Task представляет выполняемую или завершённую операцию; Task<string> дополнительно даёт строковый результат. async сам по себе не создаёт отдельный поток. Task.Run обычно отправляет вычислительную работу в пул потоков.
```csharp
var upperText = await Task.Run(
    () => text.ToUpperInvariant());
```
Это учебный пример: преобразование текста в верхний регистр запускается в фоне, а после ожидания результат можно использовать для обновления интерфейса. Для такой короткой операции отдельная задача обычно не нужна; здесь она показывает синтаксис. Элементы Avalonia создают и меняют в UI-потоке — потоке интерфейса. Dispatcher помогает выполнить работу в этом потоке. Нельзя считать, что любую операцию с кнопками допустимо делать внутри Task.Run.
Исключение — сигнал о невозможности нормально выполнить действие, например прочитать недоступный файл. try содержит попытку; catch обрабатывает подходящую ошибку; finally выполняет завершающие действия при выходе из блока. throw создаёт или передаёт исключение дальше. Ловить исключения полезно там, где можно объяснить проблему пользователю или восстановить состояние.
using в начале файла подключает пространство имён для коротких имён типов. using var stream = ... внутри метода имеет другой смысл: освободить ресурс при выходе из области действия. IDisposable и Dispose нужны, например, для потоков файлов и изображений. Сборщик мусора освобождает управляемую память, но своевременное закрытие файла всё равно требует правильного управления ресурсом.
# Avalonia и устройство окна
## Что описывает AXAML
Avalonia — средство создания графического интерфейса. Файл .axaml использует синтаксис XML для описания дерева элементов. Это декларативная запись: мы говорим, какие элементы нужны и как они размещены. Код .axaml.cs описывает связанные с окном действия. Их связывает x:Class, а загрузка разметки выполняется при InitializeComponent.
```xml
<Button x:Name="StartButton"
        Content="Начать" />
```
Button — кнопка. x:Name — имя для обращения из C#. Content — содержимое кнопки. Запись /> закрывает элемент без вложенных элементов. xmlns объявляет пространство имён XML: оно помогает понять, из какой библиотеки пришёл тип. URL в xmlns не означает, что приложение загружает разметку с сайта при каждом запуске.
Window — окно; Grid — сетка; StackPanel размещает элементы последовательно; TextBlock показывает текст; TextBox принимает ввод; Button выполняет действие; ComboBox предлагает выбор; CheckBox хранит состояние флажка; ScrollViewer даёт прокрутку. Border добавляет фон, рамку и внутренние отступы. TreeView отображает дерево, TabControl — вкладки.
## Как работает размещение
```xml
<Grid ColumnDefinitions="*,340">
    <TextBlock Text="Рабочая область" />
    <TextBlock Grid.Column="1" Text="Настройки" />
</Grid>
```
Учебный пример повторяет принцип тренажёра: справа фиксированная ширина 340, слева оставшееся место. * означает долю свободного пространства, Auto — размер по содержимому, число — фиксированный размер в логических единицах интерфейса. Столбцы и строки нумеруются с нуля. Поэтому Grid.Column="1" означает второй столбец.
Margin — внешний отступ, Padding — внутренний отступ между границей и содержимым. IsVisible скрывает или показывает элемент; IsEnabled разрешает или блокирует взаимодействие; IsReadOnly у TextBox запрещает редактирование. TextWrapping="Wrap" переносит длинные строки. Минимальные размеры окна задаются через MinWidth и MinHeight.
Styles задают повторяющееся оформление по селектору. Например, стиль Button меняет все подходящие кнопки, а Classes="tool" позволяет выделить отдельную группу. FluentTheme предоставляет базовый внешний вид элементов. Тема не отвечает за алгоритмы сравнения текста или сохранения файлов.
## Привязка данных и MVVM
Binding связывает свойство элемента с данными. DataContext — объект, относительно которого обычно ищут свойства привязки. Если назначить DataContext = ViewModel, то {Binding WindowTitle} получает заголовок из свойства WindowTitle модели данных. Это учебный пример привязки. x:DataType указывает ожидаемый тип данных для разметки, но сам по себе не создаёт объект и не назначает DataContext.
```xml
<TextBox Text="{Binding DocumentText, Mode=TwoWay}" />
```
TwoWay означает двустороннюю связь: ввод в поле меняет DocumentText, а изменение DocumentText в модели отражается в поле. Для обновления после изменения обычного свойства модель посылает PropertyChanged через интерфейс INotifyPropertyChanged. Без такого уведомления значение в памяти может измениться, а отображение остаться прежним.
MVVM расшифровывается как Model, View, ViewModel. Model содержит данные и правила предметной области; View — отображение; ViewModel — состояние, свойства и команды, с которыми работает View. Это способ разделить обязанности, а не обязательная библиотека. Наличие .axaml и .axaml.cs ещё не доказывает использование MVVM.
Команда ICommand предоставляет Execute для выполнения и CanExecute для проверки доступности. Один объект команды можно привязать к меню, кнопке и сочетанию клавиш. Code-behind при этом допустим для деталей самого интерфейса: фокус, положение курсора, выделение, закрытие окна.
## Путь запуска приложения
Program.Main вызывает BuildAvaloniaApp. AppBuilder.Configure<App>() выбирает класс приложения, UsePlatformDetect() подключает подходящую платформенную реализацию, LogToTrace() включает вывод диагностических сообщений в средства трассировки. StartWithClassicDesktopLifetime запускает жизненный цикл настольного приложения.
App.Initialize загружает App.axaml с темой и стилями. OnFrameworkInitializationCompleted создаёт MainWindow и назначает его главным окном. Конструктор MainWindow загружает разметку, готовит данные и подписки на события. Затем окно ожидает действий пользователя. Атрибут [STAThread] задаёт модель главного потока, нужную в том числе для совместимости с некоторыми механизмами Windows.
Avalonia позволяет строить приложения для разных платформ, однако проект настроен как настольное приложение. Сам факт применения Avalonia не означает, что уже создана и проверена версия для Android или iOS. Проверки в этом пособии относятся к данному окружению Windows.
