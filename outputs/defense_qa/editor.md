# Как устроен Markdown редактор
## Задача приложения и Markdown простыми словами
Markdown — способ добавить оформление в обычный текст с помощью небольшого количества специальных символов. Например, # в начале строки обозначает заголовок, а **слово** — жирное выделение. Сам файл остаётся текстовым: в нём нет сложного устройства Word-документа. Расширения, принимаемые редактором, — .md и .markdown.
```markdown
# План проекта

Это **важная** заметка и *пояснение*.

- Открыть файл
- Проверить предпросмотр
- Сохранить результат

> Небольшая цитата

[Ссылка](https://example.com)
```
В центре редактора пользователь видит именно исходную разметку. Справа приложение строит её оформленное представление. Кнопка жирного текста вставляет звёздочки в исходник, а не применяет форматирование Word. Этот принцип нужно первым показать преподавателю.
Приложение открывает папку, показывает дерево Markdown-файлов, редактирует один документ, ищет текст в документе или папке, сохраняет изменения и экспортирует HTML. Дополнительно есть отмена и повтор, форматирование, три режима отображения, горячие клавиши и предупреждения о несохранённой работе.
HTML — язык разметки веб-страниц. Экспорт превращает Markdown в отдельный HTML-файл, который можно открыть браузером. Сохранение .md и экспорт .html — разные операции: HTML не становится новым исходным документом и не снимает признак несохранённых правок Markdown.

Интерфейс из автоматического теста: слева дерево файлов, в центре исходный текст, справа предпросмотр. Верхняя панель содержит файловые действия и режимы отображения, панель над текстом — вставку разметки. Внизу показаны состояние, положение курсора, количество знаков и строк, кодировка.

## Разделение по MVVM
View — MainWindow.axaml и код визуального поведения в MainWindow.axaml.cs. ViewModel — EditorViewModel. Модель и сервисы — структуры документа, DocumentFiles, WorkspaceFiles и MarkdownDocument. В проекте MVVM реализован вручную: отдельного ReactiveUI или CommunityToolkit.Mvvm в ссылках проекта нет.
ViewModel знает текущий текст, путь, состояние сохранения и доступные команды. Окно знает, как поставить курсор, выделить найденное слово и переключить панели. Такое разделение позволяет тестировать большинство сценариев с FakeDialogs, не заставляя тест взаимодействовать с настоящим системным выбором файла.
Важный путь: ввод пользователя → TwoWay Binding → DocumentText в EditorViewModel → PropertyChanged → обновление заголовка и состояния → обработчик окна планирует новый предпросмотр. Другой путь: Ctrl+S → SaveCommand → SaveInternalAsync → DocumentFiles.WriteAsync → обновление savedText → исчезновение звёздочки.
## Создание окна и открытие первого файла
Program.Main и App запускают настольный жизненный цикл. В App.OnFrameworkInitializationCompleted создаётся MainWindow. После события Opened проверяется первый аргумент командной строки; если путь передан, вызывается window.ViewModel.OpenPathAsync(path). Наличие аргумента не отменяет проверки допустимого расширения и чтения файла.
MainWindow вызывает InitializeComponent, создаёт настоящие диалоги либо принимает переданные тестовые, создаёт EditorViewModel и записывает DataContext = ViewModel. Затем создаёт MarkdownPreview и подписывается на изменения модели, курсора, размера панели и закрытие окна.
Два таймера выполняют разные задачи: 180 мс — задержка предпросмотра после изменений; 220 мс — задержка поиска. Это не обещание, что тяжёлый документ будет полностью обработан за 180 мс. Интервал задаёт паузу до начала очередного обновления.
## Состояние документа
Главные внутренние значения EditorViewModel: text — текст сейчас; savedText — текст последней принятой загрузки или успешной записи; currentPath — путь либо null для нового документа; encoding — кодировка; fingerprint — отпечаток последней известной версии файла на диске.
```csharp
public bool IsDirty => text != savedText;
public string DisplayName => FileName + (IsDirty ? " *" : "");
```
IsDirty означает «текущий текст отличается от сохранённого». Если напечатать букву, а затем отменить изменение до исходного текста, признак снова станет false. Звёздочка — только видимый результат проверки. У нового пустого документа IsDirty может быть false, но SaveState всё равно покажет «Не сохранён», поскольку пути ещё нет.
DocumentText — свойство с дополнительной логикой. При записи нового текста оно сравнивает старое и новое значение, сохраняет новое, отправляет Changed для зависимых свойств и отменяет старый поиск. В числе обновлений — IsDirty, DisplayName, WindowTitle, Statistics и SaveState. Changed вызывает событие PropertyChanged.
Statistics считает text.Length и количество символов '\n' плюс один. Поэтому пустой документ имеет одну строку. Это число логических строк, а не число визуальных переносов по ширине окна. Положение курсора также вычисляется по переводам строк, а не по строкам, появившимся из-за TextWrapping.
## Команды и занятость
AsyncCommand реализует ICommand. В конструкторе ему передаются действие Func<Task> и необязательная проверка Func<bool>. CanExecute возвращает доступность, Execute выполняет действие через await, Refresh посылает CanExecuteChanged, чтобы элементы интерфейса заново проверили доступность.
Например, SaveCommand вызывает RunAsync и SaveInternalAsync. К одной команде привязаны кнопка, меню и сочетание клавиш. Это избавляет от трёх разных реализаций сохранения. AsyncCommand.Execute имеет async void из-за сигнатуры ICommand; основную асинхронную работу удобнее держать в методах, возвращающих Task, как и сделано здесь.
RunAsync не запускает новую файловую операцию, если IsBusy уже true. На время действия он устанавливает IsBusy = true, затем в finally возвращает false. IsEditable вычисляется как !busy. Окно и команды блокируют редактирование и конфликтующие действия на время файловой операции.
RunAsync перехватывает предусмотренные ошибки чтения, доступа, аргументов и неподдерживаемых операций, меняет Status и показывает сообщение через IEditorDialogs. Это центральное место обычной обработки ошибок. Такой обработчик не означает, что абсолютно любое исключение во всём приложении будет безопасно обработано.
## Открытие файла по шагам
1. Пользователь выбирает файл в системном диалоге либо дереве. При отмене диалог возвращает null, действие прекращается.
2. OpenInternalAsync проверяет путь: повторное открытие уже текущего пути пропускается, расширение должно быть .md или .markdown.
3. MayDiscardAsync выясняет, можно ли заменить текущий документ. Если есть изменения, требуется решение пользователя.
4. DocumentFiles.ReadAsync читает файл, определяет кодировку, получает текст и SHA-256 отпечаток байтов. Только после успешного чтения вызывается SetDocument.
5. SetDocument одновременно устанавливает путь, текущий и сохранённый текст, кодировку и отпечаток. Отправляет уведомления и DocumentLoaded. Окно очищает историю Undo, возвращает курсор и предпросмотр в начало.
Почему сначала читаем, а потом заменяем состояние? Если файл не существует или чтение не удалось, предыдущий текст должен остаться в памяти. В тестах проверяется именно это. Очистка Undo при новом документе предотвращает восстановление текста прошлого файла в новом документе.
## Несохранённые изменения и закрытие
MayDiscardAsync при IsDirty = false сразу разрешает действие. Иначе показывает три варианта: «Сохранить», «Не сохранять», «Отмена». «Не сохранять» разрешает продолжение; «Отмена» запрещает; «Сохранить» разрешает продолжение только если сохранение действительно завершилось успешно.
Ключевой случай: пользователь выбрал «Сохранить», а затем отменил выбор имени файла. Это не является успешным сохранением. SaveInternalAsync возвращает false, поэтому новый документ, открытие другого файла или закрытие не продолжаются. Правки остаются на месте.
При закрытии окна обработчик сначала ставит e.Cancel = true, потому что решение требует асинхронного диалога. Если CanCloseAsync разрешил закрытие, allowClose становится true и Close вызывается ещё раз. closingPrompt защищает от нескольких одновременных диалогов. Так обычное закрытие окна согласовано с асинхронным вопросом пользователю.
EditorDialogs.ShowAsync возвращает безопасное значение отмены при закрытии диалога крестиком. Это важно для enum SaveDecision: первый элемент Save имеет числовое значение по умолчанию, но закрытие крестиком не должно случайно трактоваться как «Сохранить».
## Чтение байтов и кодировка
Файл на диске — последовательность байтов. Кодировка объясняет, как превратить байты в буквы и обратно. Неправильная кодировка может испортить кириллицу. BOM — необязательная последовательность байтов в начале файла, по которой можно распознать определённую кодировку и порядок байтов.
DocumentFiles поддерживает UTF-8 без BOM и с BOM, UTF-16 и UTF-32 при наличии распознаваемого BOM. Без BOM предполагается строгий UTF-8. Windows-1251 автоматически не определяется. Если последовательность байтов недопустима для выбранной кодировки, чтение отклоняется, а не подменяет молча буквы.
Проверка UTF-32 выполняется раньше UTF-16, потому что некоторые сигнатуры начинаются одинаково. Метод DetectEncoding возвращает кодировку и количество начальных байтов, которые нужно пропустить перед декодированием. При записи используется сохранённая кодировка вместе с её преамбулой.
Лимит документа — 4 × 1024 × 1024 байт. Он проверяется и перед чтением, и во время чтения частями по 8192 байта: файл мог увеличиться после первой проверки. Это ограничение на размер в байтах, а не на четыре миллиона букв. Перед записью также проверяется размер получившихся байтов.
LoadedDocument — record с Path, Text, Encoding и Fingerprint. Record удобен как контейнер связанных данных и по умолчанию поддерживает сравнение по значениям своих членов. Само слово record не превращает всё содержимое, включая вложенные объекты, в абсолютно неизменяемое.
## Сохранение и защита от чужих изменений
SaveInternalAsync выбирает целевой путь. Для нового документа или «Сохранить как» открывает диалог. Проверяет расширение; при выборе другого существующего файла спрашивает о замене. Затем берёт snapshot текущего текста: конкретное содержимое, которое собирается записать.
DocumentFiles.WriteAsync кодирует snapshot в байты и записывает их в уникальный временный файл в том же каталоге. Прежде чем заменить оригинал, он сравнивает его текущий отпечаток с expectedFingerprint, если тот передан. Отпечаток — SHA-256 от байтов, а не дата изменения.
```csharp
if (expectedFingerprint is not null && !overwriteConflict &&
    (!File.Exists(path) ||
     !await MatchesFingerprintAsync(path, expectedFingerprint)))
    throw new FileConflictException();
```
Это реальный фрагмент проверки. Если ожидалась прежняя версия, а файла уже нет или его байты отличаются, создаётся FileConflictException. ViewModel перехватывает это специальное исключение и спрашивает пользователя, хочет ли он заменить файл текущим текстом.
Если пользователь отменил замену, внешний файл остаётся на диске, а текущие правки сохраняются в памяти как несохранённые. Если согласился, запись повторяется с разрешением замены. При успехе обновляются currentPath, fingerprint и savedText, после чего исчезает звёздочка и обновляется дерево выбранной папки.
SHA-256 здесь используется как отпечаток для сравнения версий. Это не шифрование текста и не механизм восстановления предыдущей версии. Файл хранится обычным текстом. Проверка уменьшает риск случайно затереть чужие изменения, но между сравнением и заменой остаётся небольшое окно гонки. Блокировки для полноценного совместного редактирования здесь нет.
Временный файл защищает от преждевременного обрезания оригинала при ошибке подготовки записи. Его остаток удаляется в finally. Нельзя называть это полной системой транзакций или резервного копирования. Автосохранения и постоянной истории версий в проекте нет.
## Как Markdig превращает разметку в структуру
MarkdownDocument.Pipeline создаётся через MarkdownPipelineBuilder. Подключены таблицы с вертикальными чертами, списки задач, дополнительные выделения, автоматические ссылки и идентификаторы заголовков. DisableHtml отключает интерпретацию встроенного HTML. Набор расширений задан явно.
MarkdownDocument.Parse возвращает дерево синтаксических элементов — AST. Это описание смысла частей текста. Например, строка «# Привет» становится HeadingBlock, обычный абзац — ParagraphBlock, жирный фрагмент — EmphasisInline внутри строки. Блоки описывают крупные части, inline-элементы — содержимое внутри них.
Дальше есть два направления. Для предпросмотра MarkdownPreview обходит AST и создаёт элементы Avalonia. Для экспорта Markdig формирует HTML, который помещается в готовый документ с заголовком, стилями и метаданными. Предпросмотр не является встроенным браузером и не отображает HTML-страницу через WebView.
## Предпросмотр и защита от устаревшего результата
При каждом изменении SchedulePreview увеличивает renderVersion, останавливает и вновь запускает таймер. Если печатать быстро, таймер постоянно откладывается до короткой паузы. Такой приём называется debounce: дорогая операция не запускается на каждое мгновенное изменение.
RefreshPreviewAsync получает очередной номер версии и снимок текста, затем вызывает разбор в Task.Run. Пока разбор идёт, пользователь может уже изменить текст. После await метод сравнивает свою версию с renderVersion. Если версия устарела или окно закрыто, результат не показывается.
```csharp
var version = ++renderVersion;
var text = ViewModel.DocumentText;
var document = await Task.Run(() => MarkdownDocument.Parse(text));
if (disposed || version != renderVersion) return;
preview.Render(document, ViewModel.CurrentPath,
    PreviewPane.Bounds.Width);
```
Это фрагмент основного алгоритма. Представь, что старый большой текст разбирался дольше нового короткого. Проверка номера не позволит позднему старому результату заменить актуальный. При этом работа старого парсера не обязательно прерывается: её результат просто отбрасывается. Отмена поиска устроена иначе, через CancellationToken.
MarkdownPreview.Render очищает прежние визуальные элементы, освобождает старые Bitmap, сбрасывает якоря заголовков и заново создаёт элементы. Заголовки становятся SelectableTextBlock увеличенного размера, абзацы — текстовыми блоками, цитаты — Border с боковой линией, списки — панелями строк, код — моноширинным текстом с прокруткой, таблицы — Grid внутри ScrollViewer.
Fill обрабатывает содержимое строк. LiteralInline даёт Run с обычным текстом, EmphasisInline — Span с выделением, CodeInline — моноширинный Run, ссылки — кнопки, помещённые в InlineUIContainer. Span объединяет фрагменты с общим оформлением. Списки задач имеют флажки только для показа: щелчок не редактирует исходник.
## Ссылки изображения и HTML
Ссылка вида #заголовок ищется в словаре anchors, который связывает идентификатор с элементом управления. BringIntoView прокручивает его в видимую область. Локальная ссылка на Markdown открывается как документ приложения. http, https и mailto передаются системному Launcher. Другие неподдерживаемые варианты вызывают сообщение.
Локальное растровое изображение загружается из файла относительно пути документа или по абсолютному пути. Предусмотрен предел 16 МБ и декодирование до ширины 1200. На экране картинка ограничивается шириной панели и высотой 400, пропорции сохраняются. Bitmap сохраняются в списке и освобождаются через Dispose при следующем обновлении или закрытии.
Сетевые изображения автоматически в предпросмотр не скачиваются. Вместо недоступной картинки появляется кнопка с подписью. Для веб-адреса её нажатие открывает ссылку через браузер. Несохранённый документ не имеет исходной папки для разрешения относительного локального пути: сначала полезно сохранить .md рядом с ресурсами.
Экспорт получает HTML через Markdig, экранирует заголовок WebUtility.HtmlEncode, добавляет UTF-8, CSS и Content-Security-Policy. Встроенный HTML исходника не исполняется как произвольная разметка. CSP ограничивает ресурсы и скрипты, однако это не обещание абсолютной безопасности любых внешних ссылок и любых браузеров.
Если исходный документ сохранён, относительные адреса ресурсов при экспорте приводятся к абсолютным URI относительно исходного пути. Это помогает открыть экспорт на том же компьютере из другой папки. Изображения внутрь HTML не упаковываются: для переноса нужно перенести ресурсы и проверить адреса. Абсолютный локальный путь сам по себе не переносим на чужой компьютер.
## Дерево папок и поиск
WorkspaceFiles.ReadTree рекурсивно строит FileNode. У узла есть Name, FullPath, IsDirectory и Children. Для папки Children содержит вложенные элементы, для файла — пустой список. TreeDataTemplate в AXAML повторяет один шаблон отображения для каждого уровня дерева.
В дереве предусмотрен бюджет около 10 000 просматриваемых элементов и ограничение глубины около 30 уровней. Это защитные пороги, а не обещание показать ровно 10 000 строк. Скрытые, системные, недоступные элементы и reparse points пропускаются; каталоги bin, obj и node_modules исключены. Папки и Markdown-файлы сортируются по именам.
Поиск по папке использует отдельный обход EnumerateMarkdown с очередью Queue. В отличие от построения дерева, у этого обхода нет того же бюджета 10 000 и глубины 30. Он может найти файл, который не попал в ограниченное дерево. Итоговый список совпадений ограничен 500 и поддерживает отмену.
Find выполняет буквальный поиск через IndexOf с учётом регистра или без него. Это не регулярные выражения. После совпадения смещение увеличивается на длину запроса, поэтому перекрывающиеся совпадения пропускаются. Например, запрос «аа» в «ааа» даст одно совпадение.
SearchHit хранит путь, имя файла, строку, столбец, Offset, Length и Snippet. Offset начинается с нуля и удобен для выделения в TextBox; строка и столбец показываются пользователю с единицы. Snippet — короткий фрагмент текста вокруг результата.
```text
Текст:   абв\r\nтест тест
Запрос:  тест
Результат 1: строка 2, столбец 1, Offset 5
Результат 2: строка 2, столбец 6, Offset 10
```
Такой случай проверяется тестом. \r\n содержит две кодовые единицы, поэтому первая «т» находится по индексу 5. При переходе из результата окно выделяет текст через SelectionStart и SelectionEnd, а ScrollToLine использует номер строки с нуля.
Поиск текущего документа работает по тексту в памяти, включая несохранённые изменения. При поиске по папке для уже открытого файла тоже используется его текущий буфер; остальные файлы читаются с диска. Это предотвращает ситуацию, когда пользователь ищет новое слово и не находит его только потому, что ещё не сохранил документ.
SearchAsync отменяет предыдущий запрос через CancellationTokenSource. Новый запрос берёт снимок текста, строки поиска, папки и параметров. При изменении этих данных предыдущие результаты очищаются. Чтобы узнать, есть ли больше 500 совпадений, алгоритм допускает поиск 501-го и показывает 500 с признаком продолжения.
Недоступные, неподходящие по кодировке или слишком большие файлы могут быть пропущены, и их количество отражается в итоге. При открытии результата из другого файла совпадения вычисляются заново и выбирается ближайшее к прежнему смещению: файл мог измениться после поиска. Постоянного индекса, как у большой поисковой системы, здесь нет.
## Форматирование отмена и режимы
Format берёт выделенный текст и добавляет prefix и suffix. Для bold это ** с обеих сторон, для italic — *, для code — обратные кавычки, для link — квадратные скобки и адрес. Если выделения нет, вставляется текст-заготовка, который сразу выделяется для замены.
Заголовок, цитата и список работают с началом строки. Метод находит предыдущий '\n' и вставляет #, > или - с пробелом. При многострочном выделении префикс добавляется также после переводов строк. Это простые операции со строкой и выделением, а не полноценное структурное редактирование AST.
Undo и Redo предоставлены самим TextBox Avalonia. Проект не реализует собственный стек истории. При загрузке другого документа IsUndoEnabled временно выключается и включается, чтобы очистить историю старого текста.
ApplyMode показывает только редактор, только предпросмотр или обе панели. Он меняет IsVisible и ColumnDefinitions. При переходе к результату поиска из режима чтения окно возвращается в раздельный режим, чтобы найденное выделение было видно.
Горячие клавиши: Ctrl+N — новый документ; Ctrl+O — файл; Ctrl+Shift+O — папка; Ctrl+S — сохранение; Ctrl+Shift+S — «Сохранить как»; Ctrl+E — HTML; Ctrl+F — поиск; Ctrl+B и Ctrl+I — выделение в редакторе; Esc — закрыть поиск. Отмена и повтор используют функции TextBox и кнопки интерфейса.

## Запуск и перенос
Команды ниже выполняются из папки MarkdownEditor. Для сборки README требует .NET SDK 10. Открыть решение можно в подходящей среде разработки, а команды выполнить в терминале.
```text
dotnet restore MarkdownEditor.slnx --configfile NuGet.Config
dotnet run --project MarkdownEditor.App
dotnet test MarkdownEditor.Tests
```
Start.cmd сначала использует готовую сборку, если она имеется, иначе запускает проект через SDK. Перед защитой нужно проверить именно тот способ запуска, который будет использован перед преподавателем.
```text
dotnet publish MarkdownEditor.App -c Release -r win-x64 --self-contained true -o bin/Release/win-x64
```
По README готовое приложение находится в bin/Release/win-x64/MarkdownEditor.exe. Для переноса копируют всю папку win-x64, а не только .exe. Самостоятельная сборка включает необходимые компоненты .NET, но остаётся сборкой под конкретную платформу и архитектуру Windows x64.
Если предпросмотр картинки пустой, сначала проверь, сохранён ли Markdown и правильный ли относительный путь. Если кириллица не читается, проверь кодировку: Windows-1251 не входит в автоматическое определение. Если файл не открывается, проверь расширение, размер и доступ. Проблемы запуска SDK и проблемы содержимого документа — разные причины.
## Ограничения которые важно назвать
Открыт один документ; вкладок с несколькими файлами нет. Нет автосохранения, базы SQL, облачной синхронизации, учётных записей, совместного редактирования и постоянной истории версий. Дерево обновляется кнопкой, загрузкой папки и после сохранения; постоянного наблюдателя за внешними изменениями каталога не реализовано.
Предпросмотр строится собственными элементами Avalonia и может отличаться от HTML в браузере по оформлению и отдельным деталям. Нет полноценного редактирования «как в Word», произвольного встроенного HTML, автоматической загрузки сетевых картинок и подсветки синтаксиса всех языков программирования. Флажки задач в предпросмотре не интерактивны.
Полный текст разбирается заново, а визуальные элементы перестраиваются; у очень сложного документа даже в пределах 4 МБ это может быть дорого. Порог размера не гарантирует мгновенную работу. Поиск буквальный, без замены и регулярных выражений. Защита SHA-256 обнаруживает многие конфликты, но не заменяет блокировку файла.

## Частые вопросы и понятные ответы
Что такое Markdown? Обычный текст с простыми обозначениями оформления. Например, # — заголовок, ** — жирное выделение. Файл остаётся текстовым.
Чем отличается Markdown от HTML? Markdown удобен для исходного текста человека; HTML описывает структуру веб-страницы. Экспорт преобразует одно представление в другое.
Что написал разработчик, если есть Markdig? Окно, состояние документа, команды, файлы, защиту сохранения, поиск, нативное отображение AST и интеграцию. Markdig выполняет синтаксический разбор и генерацию HTML.
Где MVVM? MainWindow — View, EditorViewModel — ViewModel, файловые и предметные компоненты Core — модель и сервисы. Связь показана Binding и DataContext.
Зачем PropertyChanged? Чтобы после изменения свойства интерфейс узнал о новом значении и перечитал привязку.
Почему TextBox связан TwoWay? Текст должен идти от модели к полю при открытии файла и от поля к модели при вводе.
Что такое команда? Объект с Execute и CanExecute. Один SaveCommand используется несколькими элементами интерфейса.
Что означает IsDirty? Текущий текст отличается от savedText. Если вернуть исходное содержимое, признак исчезает без записи.
Почему новое пустое окно не обязательно IsDirty? Пока текст равен исходной пустой строке, различий нет. Но пути нет, поэтому отдельный статус сообщает «Не сохранён».
Как работает Undo? Используется встроенная история TextBox, а при смене документа она очищается.
Зачем IEditorDialogs? ViewModel зависит от договора диалогов. В приложении показываются окна, в тестах ответы возвращаются автоматически.
Чем async отличается от отдельного потока? async разрешает await; оно само не создаёт поток. Task.Run используется для фоновых вычислений, например разбора Markdown.
Что такое debounce? Короткое откладывание работы до паузы в серии изменений. Здесь таймер перезапускается при печати.
Почему нужен renderVersion? Чтобы старый результат долгого разбора не заменил свежий. Неактуальная версия после завершения игнорируется.
Почему Core без Avalonia, если там ICommand? ICommand — общий интерфейс команд .NET. Конкретные окна Avalonia и реальные диалоги находятся в App.
Что такое AST? Дерево смысла разметки: заголовки, абзацы, списки и внутренние выделения. Preview обходит его и создаёт элементы интерфейса.
Почему нельзя просто показать HTML в браузере внутри окна? Можно было бы выбрать такой подход, но здесь реализован нативный рендерер Avalonia. Он даёт контроль над элементами, но требует самостоятельной поддержки видов Markdown.
Что хранит SHA-256? Короткий отпечаток байтов известной версии файла. По нему обнаруживаются изменения; сам текст не шифруется.
Есть ли полная защита от одновременной записи? Нет. Проверка перед заменой оставляет окно гонки, поэтому полноценное совместное редактирование не заявляется.
Зачем временный файл? Подготовка нового содержимого не обрезает оригинал. Подмена выполняется после успешной записи и проверки конфликта.
Что происходит при отмене выбора имени? SaveInternalAsync возвращает false, исходное действие не продолжается и правки остаются в памяти.
Как учитывается кириллица? Файл декодируется поддерживаемой Unicode-кодировкой; исходная кодировка запоминается для записи. Windows-1251 автоматически не определяется.
Почему поиск видит несохранённое слово? Для текущего документа берётся буфер ViewModel, а не только файл на диске.
Поиск использует регулярные выражения? Нет, IndexOf выполняет буквальное сравнение. Перекрывающиеся совпадения не включаются.
Почему дерево и поиск могут показать разные файлы? У построения дерева есть бюджет и глубина; поиск обходит папку отдельно и ограничивает число совпадений, а не тем же бюджетом дерева.
Почему экспорт не снимает звёздочку? Он записывает HTML-представление, а не текущий исходный .md. savedText при экспорте не меняется.
Можно ли запускать HTML-код из Markdown? Интерпретация встроенного HTML отключена в Pipeline. Ссылки и экспорт имеют отдельные ограничения; это не среда выполнения произвольных скриптов.
Что требуется улучшить в производительности? Полный повторный разбор и перестроение элементов могут быть дорогими. Можно исследовать частичное обновление и ограничение сложности, измерив реальное время.
## Самопроверка
Без подсказки проследи один путь: Ctrl+S → SaveCommand → RunAsync → SaveInternalAsync → WriteAsync → временный файл → проверка отпечатка → замена → savedText → PropertyChanged → исчезновение звёздочки. Если понимаешь, зачем нужен каждый шаг, можно ответить на большинство вопросов о сохранении.
Затем проследи ввод: TextBox → DocumentText → уведомление → таймер → Parse в фоне → проверка версии → MarkdownPreview.Render. Не смешивай состояние текста, разбор разметки и рисование элементов: это разные обязанности.
