1 C sharp и платформа dot NET с нуля 
Язык платформа и интерфейс 
C# читается «си шарп». Это язык, на котором мы описываем действия программы: прочитать текст, сравнить 
символы, обработать нажатие кнопки, сохранить файл. Код в файле .cs — обычный текст с правилами 
записи. Компьютеру нужно перевести его в выполняемую форму. 
.NET читается «дот нет». Это платформа: среда выполнения и большой набор готовых средств для работы 
со строками, файлами, временем и коллекциями. C# — язык инструкций, .NET — средства для их 
выполнения. Avalonia — библиотека для построения окон и элементов  интерфейса поверх .NET. Это три 
связанные, но разные вещи. 
Представь мастерскую. C# — язык, на котором написано задание мастеру. .NET — оборудование и общие 
инструменты. Avalonia — набор деталей для панели управления: окна, кнопки, поля ввода. Проект 
приложения соединяет всё это и добавляет собственные правила раб оты. 
SDK — набор для разработчика. В нём есть инструменты сборки, компилятор и средства запуска. Runtime 
— среда выполнения готового приложения. Для изменения и сборки нужен SDK. У готовой самостоятельной 
сборки необходимые компоненты .NET могут лежать рядом с приложением. 
NuGet — система получения библиотек. PackageReference в .csproj указывает имя и версию готового пакета. 
ProjectReference связывает проекты внутри решения. Например, приложение использует классы своего Core 
через ProjectReference. Это не копирование текста исходников вручную. 
Как исходники становятся работающей программой 
Обычная последовательность такая: исходники C# и разметка Avalonia → сборка проекта → файлы приложения 
→ запуск среды .NET → создание окна → ожидание действий пользователя. В обычной сборке C# сначала получается 
промежуточный код IL; среда выполнения может  преобразовывать его в машинный код через JIT. Для 
объяснения этих проектов достаточно знать этот путь; отдельная AOT -сборка здесь не показана в 
настройках проектов. 
Программа с окном не читает весь код сверху вниз заново после каждого клика. При запуске она создаёт 
объекты и подписывает обработчики на события. Затем работает цикл обработки событий: нажали кнопку 
— вызван соответствующий метод; изменили текст — вызван другой метод. 
Файлы .csproj описывают отдельные проекты. Решение .slnx объединяет несколько проектов для удобной 
работы. Каталог bin содержит результаты сборки, obj — промежуточные файлы. Править поведение 
приложения следует в исходниках, а не в сгенерированных файлах этих каталогов. 
Переменная и тип данных 
Переменная — именованное место для значения. Тип отвечает на вопрос «какие значения здесь допустимы 
и какие операции с ними можно выполнять». Имя отвечает на вопрос «зачем это значение понадобилось».  
int errors = 2; 
double accuracy = 97.5; 
bool isActive = true; 
string text = "Привет"; 
char letter = 'П';

int хранит целое число; double — число с дробной частью; bool — true или false; string — строку; char — одну 
кодовую единицу UTF-16. В обычном русском и английском тексте отдельная буква обычно занимает один 
char. Однако эмодзи и некоторые сложные символы могут занимать несколько единиц: String.Length не 
является универсальным счётчиком видимых знаков. 
Знак = присваивает значение. Знак == сравнивает два значения. Поэтому errors = 2 означает «записать 2», 
а errors == 2 — «проверить, равно ли значение двум». Точка с запятой завершает многие инструкции. Строки 
пишутся в двойных кавычках, отдельные char — в одинарных. 
var count = 10; 
var caption = "Готово"; 
var не означает «любой тип». Компилятор выводит тип из правой части: count будет int, caption — string. 
После этого нельзя просто записать строку в count. Такой вывод типа сокращает запись, сохраняя проверку 
типов. 
Условия циклы и индексы 
if (errors == 0) 
{ 
    return "Без ошибок"; 
} 
return "Есть ошибки"; 
Это учебный фрагмент тела метода, возвращающего string. if означает «если». Условие в круглых скобках 
должно дать bool. Фигурные скобки объединяют инструкции. return возвращает результат и сразу 
прекращает текущий вызов метода. В методе void можно написать просто return, чтобы выйти без значения. 
for (var i = 0; i < text.Length; i++) 
{ 
    var symbol = text[i]; 
} 
for повторяет действия. i = 0 — старт; i < text.Length — условие продолжения; i++ — увеличение на единицу 
после прохода. Индексы начинаются с нуля: в строке «кот» text[0] — «к», text[1] — «о», text[2] — «т». 
Обращение за пределы строки вызывает ошибку. for each перебирает готовые элементы коллекции без 
ручного управления индексом. 
Частые операторы: != — не равно; !flag — противоположное логическое значение; && — одновременно 
выполнены оба условия; || — выполнено хотя бы одно. В выражении a && b правая часть не вычисляется, 
если a уже false. Тернарная запись condition ? yes : no выбирает одно из двух значений. 
Класс объект поле и свойство 
Класс — описание устройства определённой сущности. Объект — конкретный экземпляр такого класса в 
памяти. Один класс настроек позволяет создать несколько объектов с разными настройками. new создаёт 
экземпляр, а конструктор задаёт его начальное состояние. 
public sealed class TrainerSettings 
{ 
    public float FontSize { get; set; } = 16f; 
    public bool ShowKeyboard { get; set; } = true; 
} 
Это фрагмент реального класса тренажёра. class объявляет класс. public делает его доступным другим 
частям программы. sealed запрещает создавать классы -наследники от него. FontSize и ShowKeyboard —

свойства. get разрешает чтение, set — изменение. = 16f задаёт начальное значение float; суффикс f уточняет 
тип числа. У свойства bool без явного начального значения исходное значение false.  
var settings = new TrainerSettings(); 
settings.FontSize = 24; 
Первая строка создаёт объект. Вторая меняет его свойство. Точка означает обращение к члену объекта. 
Поле хранит данные непосредственно внутри класса; свойство предоставляет доступ к данным и при 
необходимости выполняет дополнительную логику. Поэтому свойст во может не хранить отдельное 
значение, а вычислять его при чтении. 
public bool IsDirty => text != savedText; 
Это реальное вычисляемое свойство редактора: «есть несохранённые изменения, если текущий текст 
отличается от сохранённого». => здесь сокращает запись тела свойства. У свойства нет set: присвоить ему 
true вручную нельзя. Нужно изменить text или savedText, и результат сравнения изменится. 
private разрешает обращаться к члену только внутри содержащего типа. public открывает доступ извне. 
internal ограничивает доступ сборкой. readonly запрещает переприсваивать поле после допустимой 
инициализации; но если поле содержит список, это само по себе  не запрещает добавлять элементы в 
список. const задаёт константу времени компиляции. 
Метод и конструктор 
Метод — именованное действие. Параметры — входные данные, возвращаемое значение — результат. 
Вызов session.Start(text, true) означает «попросить объект session начать попытку с данным текстом и учётом 
регистра». Тип void означает, что метод не возвращает значение. 
public void Reset() 
{ 
    IsActive = false; 
    IsComplete = false; 
} 
Это сокращённый учебный фрагмент сброса состояния. Reset — имя метода, пустые круглые скобки 
означают отсутствие параметров. В настоящем методе тренажёра также очищаются строки и время. 
Конструктор носит имя класса, не имеет типа возвращаемого значения и вызывается при new. 
В коде встречается современная запись конструктора прямо возле имени класса: 
TypingSession(TimeProvider? timeProvider = null). Это первичный конструктор. Параметр со значением по 
умолчанию разрешено не передавать. Он нужен для выбора источника времени, в т ом числе тестового. 
Наследование интерфейсы и основы ООП 
ООП — способ организовать программу вокруг объектов, их данных и действий. На защите полезно 
объяснить три идеи на конкретных примерах. Инкапсуляция: внутреннее состояние меняется через методы 
и свойства с контролируемым доступом. Наследование: MainWindow : Window расширяет готовое окно 
Avalonia. Полиморфизм: код может работать с разными реализациями одного интерфейса через общий 
договор. 
Интерфейс перечисляет возможности, которые обязан предоставить объект. IEditorDialogs описывает 
выбор файла и вопросы пользователю. Настоящий EditorDialogs показывает окна, а FakeDialogs в тестах 
заранее возвращает ответы. EditorViewModel обращается к дого вору IEditorDialogs, поэтому его легче 
проверять без ручных кликов.

Композиция означает, что объект содержит другие объекты: MainWindow хранит TypingSession или

Коллекции и LINQ 
List<T> — изменяемый список элементов типа T. List<TypingSessionStats> хранит результаты попыток. 
Dictionary<TKey, TValue> сопоставляет ключу значение: Dictionary<char, Border> позволяет найти 
изображение клавиши по символу. Здесь Dictionary — структура данных C#, а WordDictionary — собственный 
класс приложения, несмотря на похожие названия. 
IReadOnlyList<T> предоставляет чтение списка через данный интерфейс. Queue<T> — очередь: первый 
добавленный элемент извлекается первым. Она используется при обходе папок. Запись [] в подходящем 
контексте создаёт пустую коллекцию. Угловые скобки задают пара метр типа; это называется обобщением, 
или generics. 
LINQ — набор операций над последовательностями. Where отбирает элементы, Select преобразует каждый 
элемент, OrderByDescending сортирует по убыванию, Take оставляет первые N, ToList материализует 
результат в список. Max находит максимум, Average — среднее, GroupBy собирает элементы в группы. 
statistics.OrderByDescending(item => item.Date) 
          .Take(500) 
          .ToList(); 
Это цепочка из тренажёра. Сначала самые новые результаты оказываются впереди, затем сохраняются 
только первые 500, затем получается отдельный список. item => item.Date — лямбда: маленькая функция 
«для данного элемента взять его дату». => может обозначать лямбду или краткое тело члена класса; смысл 
определяется контекстом. 
Пустое значение и короткие записи 
null означает отсутствие объекта или значения ссылки. Пустая строка "" существует и имеет длину ноль; null 
означает, что строки нет. string? показывает, что отсутствие допустимо. Настройка Nullable в .csproj 
помогает компилятору предупреждать об опасных обращениях. 
InputBox.Text ?? "" читается «взять Text, а если там null, использовать пустую строку». Выражение 
document?.Path читает Path только при наличии document, иначе даёт null. Знак ! после выражения, 
например Inlines!, подавляет предупреждение компилятора о nul l, но не создаёт объект и не защищает во 
время выполнения. 
is проверяет тип или шаблон. is not WordDictionary text означает «если значение не удалось распознать как 
WordDictionary и получить переменную text». switch выбирает ветку по значению или типу. nameof(IsDirty) 
даёт строку с именем члена; при переименовании  инструменты могут обновить ссылку безопаснее, чем 
обычный текст в кавычках. 
$"Ошибок: {errors}" вставляет значение в строку. Формат :F1 показывает одну цифру после десятичного 
разделителя, :F0 — число без дробной части. Это меняет отображение, а не сам расчёт. \n в строке означает 
перевод строки. // начинает комментарий для человека.

События асинхронность и освобождение ресурсов 
Событие — уведомление о том, что что -то произошло. Обработчик — код, который реагирует. Запись 
button.Click += ... подписывает обработчик; -= снимает подписку. Подписка не нажимает кнопку немедленно. 
В выражении (_, _) => StartSession() параметры события н е используются, а после события вызывается 
StartSession. 
async и await позволяют описать ожидание операции без блокирующего ожидания потока в точке 
незавершённого await. Task представляет выполняемую или завершённую операцию; Task<string> 
дополнительно даёт строковый результат. async сам по себе не создаёт отдел ьный поток. Task.Run обычно 
отправляет вычислительную работу в пул потоков. 
var document = await Task.Run( 
    () => MarkdownDocument.Parse(text)); 
Это фрагмент редактора: разбор Markdown запускается в фоне, а после ожидания результат используется 
для обновления интерфейса. Элементы Avalonia создают и меняют в UI -потоке — потоке интерфейса. 
Dispatcher помогает выполнить работу в этом потоке. Нельзя сч итать, что любую операцию с кнопками 
допустимо делать внутри Task.Run. 
Исключение — сигнал о невозможности нормально выполнить действие, например прочитать недоступный 
файл. try содержит попытку; catch обрабатывает подходящую ошибку; finally выполняет завершающие 
действия при выходе из блока. throw создаёт или передаёт исключение дальше. Ловить исключения полезно 
там, где можно объяснить проблему пользователю или восстановить состояние.  
using в начале файла подключает пространство имён для коротких имён типов. using var stream = ... внутри 
метода имеет другой смысл: освободить ресурс при выходе из области действия. IDisposable и Dispose 
нужны, например, для потоков файлов и изображений. Сборщик мусора освобождает управляемую память, 
но своевременное закрытие файла всё равно требует правильного управления ресурсом.  
2 Avalonia и устройство окна 
Что описывает AXAML 
Avalonia — средство создания графического интерфейса. Файл .axaml использует синтаксис XML для 
описания дерева элементов. Это декларативная запись: мы говорим, какие элементы нужны и как они 
размещены. Код .axaml.cs описывает связанные с окном действия. Их  связывает x:Class, а загрузка 
разметки выполняется при InitializeComponent. 
<Button x:Name="StartButton" 
        Content="Начать" /> 
Button — кнопка. x:Name — имя для обращения из C#. Content — содержимое кнопки. Запись /> закрывает 
элемент без вложенных элементов. xmlns объявляет пространство имён XML: оно помогает понять, из какой 
библиотеки пришёл тип. URL в xmlns не означает, что пр иложение загружает разметку с сайта при каждом 
запуске. 
Window — окно; Grid — сетка; StackPanel размещает элементы последовательно; TextBlock показывает 
текст; TextBox принимает ввод; Button выполняет действие; ComboBox предлагает выбор; CheckBox хранит 
состояние флажка; ScrollViewer даёт прокрутку. Border доба вляет фон, рамку и внутренние отступы. 
TreeView отображает дерево, TabControl — вкладки.

Как работает размещение 
<Grid ColumnDefinitions="*,340"> 
    <TextBlock Text="Рабочая область" /> 
    <TextBlock Grid.Column="1" Text="Настройки" /> 
</Grid> 
Учебный пример повторяет принцип тренажёра: справа фиксированная ширина 340, слева оставшееся 
место. * означает долю свободного пространства, Auto — размер по содержимому, число — фиксированный 
размер в логических единицах интерфейса. Столбцы и строки нумеруются с нуля. Поэтому Grid.Column="1" 
означает второй столбец. 
Margin — внешний отступ, Padding — внутренний отступ между границей и содержимым. IsVisible скрывает 
или показывает элемент; IsEnabled разрешает или блокирует взаимодействие; IsReadOnly у TextBox 
запрещает редактирование. TextWrapping="Wrap" переносит длин ные строки. Минимальные размеры окна 
задаются через MinWidth и MinHeight. 
Styles задают повторяющееся оформление по селектору. Например, стиль Button меняет все подходящие 
кнопки, а Classes="tool" позволяет выделить отдельную группу. FluentTheme предоставляет базовый 
внешний вид элементов. Тема не отвечает за алгоритмы сравнения текста или сохранения файлов. 
Привязка данных и MVVM 
Binding связывает свойство элемента с данными. DataContext — объект, относительно которого обычно 
ищут свойства привязки. В редакторе DataContext = ViewModel, поэтому {Binding WindowTitle} получает 
заголовок из EditorViewModel. x:DataType указывает ожидаем ый тип данных для разметки, но сам по себе 
не создаёт объект и не назначает DataContext. 
<TextBox Text="{Binding DocumentText, Mode=TwoWay}" /> 
TwoWay означает двустороннюю связь: ввод в поле меняет DocumentText, а изменение DocumentText в 
модели отражается в поле. Для обновления после изменения обычного свойства модель посылает 
PropertyChanged через интерфейс INotifyPropertyChanged. Без такого уведомления значение в памяти может 
измениться, а отображение остаться прежним. 
MVVM расшифровывается как Model, View, ViewModel. Model содержит данные и правила предметной 
области; View — отображение; ViewModel — состояние, свойства и команды, с которыми работает View. Это 
способ разделить обязанности, а не обязательная библиотека. Наличие .axaml и .axaml.cs ещё не доказывает 
использование MVVM. 
Команда ICommand предоставляет Execute для выполнения и CanExecute для проверки доступности. Один 
объект команды можно привязать к меню, кнопке и сочетанию клавиш. Code-behind при этом допустим для 
деталей самого интерфейса: фокус, положение курсора, выделение, закрытие окна.

Состояние документа

Команды и занятость 
AsyncCommand реализует ICommand. В конструкторе ему передаются действие Func<Task> и 
необязательная проверка Func<bool>. CanExecute возвращает доступность, Execute выполняет действие 
через await, Refresh посылает CanExecuteChanged, чтобы элементы интерфейс а заново проверили 
доступность. 
Например, SaveCommand вызывает RunAsync и SaveInternalAsync. К одной команде привязаны кнопка, меню 
и сочетание клавиш. Это избавляет от трёх разных реализаций сохранения. AsyncCommand.Execute имеет 
async void из -за сигнатуры ICommand; основную асинхронную  работу удобнее держать в методах, 
возвращающих Task, как и сделано здесь. 
RunAsync не запускает новую файловую операцию, если IsBusy уже true. На время действия он 
устанавливает IsBusy = true, затем в finally возвращает false. IsEditable вычисляется как !busy. Окно и 
команды блокируют редактирование и конфликтующие действия на время файловой операции. 
RunAsync перехватывает предусмотренные ошибки чтения, доступа, аргументов и неподдерживаемых 
операций, меняет Status и показывает сообщение через IEditorDialogs. Это центральное место обычной 
обработки ошибок. Такой обработчик не означает, что абсолютно лю бое исключение во всём приложении 
будет безопасно обработано.

Несохранённые изменения и закрытие 
MayDiscardAsync при IsDirty = false сразу разрешает действие. Иначе показывает три варианта: «Сохранить», 
«Не сохранять», «Отмена». «Не сохранять» разрешает продолжение; «Отмена» запрещает; «Сохранить» 
разрешает продолжение только если сохранение действительно завершилось успешно. 
Ключевой случай: пользователь выбрал «Сохранить», а затем отменил выбор имени файла. Это не является 
успешным сохранением. SaveInternalAsync возвращает false, поэтому новый документ, открытие другого 
файла или закрытие не продолжаются. Правки остаются на месте. 
При закрытии окна обработчик сначала ставит e.Cancel = true, потому что решение требует асинхронного 
диалога. Если CanCloseAsync разрешил закрытие, allowClose становится true и Close вызывается ещё раз. 
closingPrompt защищает от нескольких одновременных ди алогов. Так обычное закрытие окна согласовано 
с асинхронным вопросом пользователю. 
EditorDialogs.ShowAsync возвращает безопасное значение отмены при закрытии диалога крестиком. Это 
важно для enum SaveDecision: первый элемент Save имеет числовое значение по умолчанию, но закрытие 
крестиком не должно случайно трактоваться как «Сохранить». 
Чтение байтов и кодировка 
Файл на диске — последовательность байтов. Кодировка объясняет, как превратить байты в буквы и 
обратно. Неправильная кодировка может испортить кириллицу. BOM — необязательная 
последовательность байтов в начале файла, по которой можно распознать определённу ю кодировку и 
порядок байтов. 
DocumentFiles поддерживает UTF-8 без BOM и с BOM, UTF-16 и UTF-32 при наличии распознаваемого BOM. 
Без BOM предполагается строгий UTF -8. Windows -1251 автоматически не определяется. Если 
последовательность байтов недопустима для выбранной кодировки, чтение отклоняется, а не подменяет 
молча буквы. 
Проверка UTF -32 выполняется раньше UTF -16, потому что некоторые сигнатуры начинаются одинаково. 
Метод DetectEncoding возвращает кодировку и количество начальных байтов, которые нужно пропустить 
перед декодированием. При записи используется сохранённая коди ровка вместе с её преамбулой. 
Лимит документа — 4 × 1024 × 1024 байт. Он проверяется и перед чтением, и во время чтения частями по 
8192 байта: файл мог увеличиться после первой проверки. Это ограничение на размер в байтах, а не на 
четыре миллиона букв. Перед записью также проверяется размер получившихся байтов.

Сохранение и защита от чужих изменений 
SaveInternalAsync выбирает целевой путь. Для нового документа или «Сохранить как» открывает диалог. 
Проверяет расширение; при выборе другого существующего файла спрашивает о замене. Затем берёт 
snapshot текущего текста: конкретное содержимое, которое собирается записать. 
DocumentFiles.WriteAsync кодирует snapshot в байты и записывает их в уникальный временный файл в том 
же каталоге. Прежде чем заменить оригинал, он сравнивает его текущий отпечаток с expectedFingerprint, 
если тот передан. Отпечаток — SHA-256 от байтов, а не дата изменения. 
if (expectedFingerprint is not null && !overwriteConflict && 
    (!File.Exists(path) || 
     !await MatchesFingerprintAsync(path, expectedFingerprint))) 
    throw new FileConflictException(); 
Это реальный фрагмент проверки. Если ожидалась прежняя версия, а файла уже нет или его байты 
отличаются, создаётся FileConflictException. ViewModel перехватывает это специальное исключение и 
спрашивает пользователя, хочет ли он заменить файл текущим тексто м. 
Если пользователь отменил замену, внешний файл остаётся на диске, а текущие правки сохраняются в 
памяти как несохранённые. Если согласился, запись повторяется с разрешением замены. При успехе 
обновляются currentPath, fingerprint и savedText, после чего исч езает звёздочка и обновляется дерево 
выбранной папки. 
SHA-256 здесь используется как отпечаток для сравнения версий. Это не шифрование текста и не механизм 
восстановления предыдущей версии. Файл хранится обычным текстом. Проверка уменьшает риск случайно 
затереть чужие изменения, но между сравнением и заменой остаётся небольшое окно гонки. Блокировки 
для полноценного совместного редактирования здесь нет. 
Временный файл защищает от преждевременного обрезания оригинала при ошибке подготовки записи. Его 
остаток удаляется в finally. Нельзя называть это полной системой транзакций или резервного копирования. 
Автосохранения и постоянной истории версий в проекте нет. 
Как Markdig превращает разметку в структуру 
MarkdownDocument.Pipeline создаётся через MarkdownPipelineBuilder. Подключены таблицы с 
вертикальными чертами, списки задач, дополнительные выделения, автоматические ссылки и 
идентификаторы заголовков. DisableHtml отключает интерпретацию встроенного HTML. Набор расширений 
задан явно. 
MarkdownDocument.Parse возвращает дерево синтаксических элементов — AST. Это описание смысла 
частей текста. Например, строка «# Привет» становится HeadingBlock, обычный абзац — ParagraphBlock, 
жирный фрагмент — EmphasisInline внутри строки. Блоки описывают  крупные части, inline -элементы — 
содержимое внутри них. 
Дальше есть два направления. Для предпросмотра MarkdownPreview обходит AST и создаёт элементы 
Avalonia. Для экспорта Markdig формирует HTML, который помещается в готовый документ с заголовком,

Предпросмотр и защита от устаревшего результата 
При каждом изменении SchedulePreview увеличивает renderVersion, останавливает и вновь запускает 
таймер. Если печатать быстро, таймер постоянно откладывается до короткой паузы. Такой приём 
называется debounce: дорогая операция не запускается на каждое мгнов енное изменение. 
RefreshPreviewAsync получает очередной номер версии и снимок текста, затем вызывает разбор в Task.Run. 
Пока разбор идёт, пользователь может уже изменить текст. После await метод сравнивает свою версию с 
renderVersion. Если версия устарела или окно закрыто, результат не показывается. 
var version = ++renderVersion; 
var text = ViewModel.DocumentText; 
var document = await Task.Run(() => MarkdownDocument.Parse(text)); 
if (disposed || version != renderVersion) return; 
preview.Render(document, ViewModel.CurrentPath, 
    PreviewPane.Bounds.Width); 
Это фрагмент основного алгоритма. Представь, что старый большой текст разбирался дольше нового 
короткого. Проверка номера не позволит позднему старому результату заменить актуальный. При этом 
работа старого парсера не обязательно прерывается: её результат просто отбрасывается. Отмена поиска 
устроена иначе, через CancellationToken. 
MarkdownPreview.Render очищает прежние визуальные элементы, освобождает старые Bitmap, сбрасывает 
якоря заголовков и заново создаёт элементы. Заголовки становятся SelectableTextBlock увеличенного 
размера, абзацы — текстовыми блоками, цитаты — Border с боковой линией, списки — панелями строк, код 
— моноширинным текстом с прокруткой, таблицы — Grid внутри ScrollViewer. 
Fill обрабатывает содержимое строк. LiteralInline даёт Run с обычным текстом, EmphasisInline — Span с 
выделением, CodeInline — моноширинный Run, ссылки — кнопки, помещённые в InlineUIContainer. Span 
объединяет фрагменты с общим оформлением. Списки задач им еют флажки только для показа: щелчок не 
редактирует исходник. 
Ссылки изображения и HTML 
Ссылка вида #заголовок ищется в словаре anchors, который связывает идентификатор с элементом 
управления. BringIntoView прокручивает его в видимую область. Локальная ссылка на Markdown 
открывается как документ приложения. http, https и mailto передаются сис темному Launcher. Другие 
неподдерживаемые варианты вызывают сообщение. 
Локальное растровое изображение загружается из файла относительно пути документа или по 
абсолютному пути. Предусмотрен предел 16 МБ и декодирование до ширины 1200. На экране картинка 
ограничивается шириной панели и высотой 400, пропорции сохраняются. Bitma p сохраняются в списке и 
освобождаются через Dispose при следующем обновлении или закрытии.  
Сетевые изображения автоматически в предпросмотр не скачиваются. Вместо недоступной картинки 
появляется кнопка с подписью. Для веб -адреса её нажатие открывает ссылку через браузер. 
Несохранённый документ не имеет исходной папки для разрешения относительног о локального пути: 
сначала полезно сохранить .md рядом с ресурсами.

Дерево папок и поиск 
WorkspaceFiles.ReadTree рекурсивно строит FileNode. У узла есть Name, FullPath, IsDirectory и Children. Для 
папки Children содержит вложенные элементы, для файла — пустой список. TreeDataTemplate в AXAML 
повторяет один шаблон отображения для каждого уровня дерева. 
В дереве предусмотрен бюджет около 10 000 просматриваемых элементов и ограничение глубины около 30 
уровней. Это защитные пороги, а не обещание показать ровно 10 000 строк. Скрытые, системные, 
недоступные элементы и reparse points пропускаются; каталоги bin, obj и node_modules исключены. Папки и 
Markdown-файлы сортируются по именам. 
Поиск по папке использует отдельный обход EnumerateMarkdown с очередью Queue. В отличие от 
построения дерева, у этого обхода нет того же бюджета 10 000 и глубины 30. Он может найти файл, который 
не попал в ограниченное дерево. Итоговый список совпадений ог раничен 500 и поддерживает отмену. 
Find выполняет буквальный поиск через IndexOf с учётом регистра или без него. Это не регулярные 
выражения. После совпадения смещение увеличивается на длину запроса, поэтому перекрывающиеся 
совпадения пропускаются. Например, запрос «аа» в «ааа» даст одно со впадение. 
SearchHit хранит путь, имя файла, строку, столбец, Offset, Length и Snippet. Offset начинается с нуля и удобен 
для выделения в TextBox; строка и столбец показываются пользователю с единицы. Snippet — короткий 
фрагмент текста вокруг результата. 
Текст:   абв\r\nтест тест 
Запрос:  тест 
Результат 1: строка 2, столбец 1, Offset 5 
Результат 2: строка 2, столбец 6, Offset 10 
Такой случай проверяется тестом. \r\n содержит две кодовые единицы, поэтому первая «т» находится по 
индексу 5. При переходе из результата окно выделяет текст через SelectionStart и SelectionEnd, а ScrollToLine 
использует номер строки с нуля. 
Поиск текущего документа работает по тексту в памяти, включая несохранённые изменения. При поиске по 
папке для уже открытого файла тоже используется его текущий буфер; остальные файлы читаются с диска. 
Это предотвращает ситуацию, когда пользователь ищет но вое слово и не находит его только потому, что 
ещё не сохранил документ. 
SearchAsync отменяет предыдущий запрос через CancellationTokenSource. Новый запрос берёт снимок 
текста, строки поиска, папки и параметров. При изменении этих данных предыдущие результаты 
очищаются. Чтобы узнать, есть ли больше 500 совпадений, алгоритм допу скает поиск 501-го и показывает 
500 с признаком продолжения.

Недоступные, неподходящие по кодировке или слишком большие файлы могут быть пропущены, и их

Форматирование отмена и режимы 
Format берёт выделенный текст и добавляет prefix и suffix. Для bold это ** с обеих сторон, для italic — *, для 
code — обратные кавычки, для link — квадратные скобки и адрес. Если выделения нет, вставляется текст -
заготовка, который сразу выделяется для замены. 
Заголовок, цитата и список работают с началом строки. Метод находит предыдущий '\n' и вставляет #, > или 
- с пробелом. При многострочном выделении префикс добавляется также после переводов строк. Это 
простые операции со строкой и выделением, а не полноценное структурное редактирование AST. 
Undo и Redo предоставлены самим TextBox Avalonia. Проект не реализует собственный стек истории. При 
загрузке другого документа IsUndoEnabled временно выключается и включается, чтобы очистить историю 
старого текста. 
ApplyMode показывает только редактор, только предпросмотр или обе панели. Он меняет IsVisible и 
ColumnDefinitions. При переходе к результату поиска из режима чтения окно возвращается в раздельный 
режим, чтобы найденное выделение было видно. 
Горячие клавиши: Ctrl+N — новый документ; Ctrl+O — файл; Ctrl+Shift+O — папка; Ctrl+S — сохранение; 
Ctrl+Shift+S — «Сохранить как»; Ctrl+E — HTML; Ctrl+F — поиск; Ctrl+B и Ctrl+I — выделение в редакторе; 
Esc — закрыть поиск. Отмена и повтор используют функции TextBox и кнопки интерфейса.

Ограничения которые важно назвать 
Открыт один документ; вкладок с несколькими файлами нет. Нет автосохранения, базы SQL, облачной 
синхронизации, учётных записей, совместного редактирования и постоянной истории версий. Дерево 
обновляется кнопкой, загрузкой папки и после сохранения; постоянн ого наблюдателя за внешними 
изменениями каталога не реализовано. 
Предпросмотр строится собственными элементами Avalonia и может отличаться от HTML в браузере по 
оформлению и отдельным деталям. Нет полноценного редактирования «как в Word», произвольного

программирования. Флажки задач в предпросмотре не интерактивны. 
Полный текст разбирается заново, а визуальные элементы перестраиваются; у очень сложного документа 
даже в пределах 4 МБ это может быть дорого. Порог размера не гарантирует мгновенную работу. Поиск 
буквальный, без замены и регулярных выражений. Защита SHA-256 обнаруживает многие конфликты, но не 
заменяет блокировку файла.

Частые вопросы и понятные ответы 
Что такое Markdown? Обычный текст с простыми обозначениями оформления. Например, # — заголовок, ** 
— жирное выделение. Файл остаётся текстовым. 
Чем отличается Markdown от HTML? Markdown удобен для исходного текста человека; HTML описывает 
структуру веб-страницы. Экспорт преобразует одно представление в другое. 
Что написал разработчик, если есть Markdig? Окно, состояние документа, команды, файлы, защиту 
сохранения, поиск, нативное отображение AST и интеграцию. Markdig выполняет синтаксический разбор и 
генерацию HTML. 
Где MVVM? MainWindow — View, EditorViewModel — ViewModel, файловые и предметные компоненты Core 
— модель и сервисы. Связь показана Binding и DataContext. 
Зачем PropertyChanged? Чтобы после изменения свойства интерфейс узнал о новом значении и перечитал 
привязку. 
Почему TextBox связан TwoWay? Текст должен идти от модели к полю при открытии файла и от поля к 
модели при вводе. 
Что такое команда? Объект с Execute и CanExecute. Один SaveCommand используется несколькими 
элементами интерфейса. 
Что означает IsDirty? Текущий текст отличается от savedText. Если вернуть исходное содержимое, признак 
исчезает без записи. 
Почему новое пустое окно не обязательно IsDirty? Пока текст равен исходной пустой строке, различий нет. 
Но пути нет, поэтому отдельный статус сообщает «Не сохранён». 
Как работает Undo? Используется встроенная история TextBox, а при смене документа она очищается.  
Зачем IEditorDialogs? ViewModel зависит от договора диалогов. В приложении показываются окна, в тестах 
ответы возвращаются автоматически. 
Чем async отличается от отдельного потока? async разрешает await; оно само не создаёт поток. Task.Run 
используется для фоновых вычислений, например разбора Markdown.  
Что такое debounce? Короткое откладывание работы до паузы в серии изменений. Здесь таймер 
перезапускается при печати.

Почему нужен renderVersion? Чтобы старый результат долгого разбора не заменил свежий. Неактуальная 
версия после завершения игнорируется. 
Почему Core без Avalonia, если там ICommand? ICommand — общий интерфейс команд .NET. Конкретные 
окна Avalonia и реальные диалоги находятся в App. 
Что такое AST? Дерево смысла разметки: заголовки, абзацы, списки и внутренние выделения. Preview 
обходит его и создаёт элементы интерфейса. 
Почему нельзя просто показать HTML в браузере внутри окна? Можно было бы выбрать такой подход, но 
здесь реализован нативный рендерер Avalonia. Он даёт контроль над элементами, но требует 
самостоятельной поддержки видов Markdown. 
Что хранит SHA -256? Короткий отпечаток байтов известной версии файла. По нему обнаруживаются 
изменения; сам текст не шифруется. 
Есть ли полная защита от одновременной записи? Нет. Проверка перед заменой оставляет окно гонки, 
поэтому полноценное совместное редактирование не заявляется.  
Зачем временный файл? Подготовка нового содержимого не обрезает оригинал. Подмена выполняется 
после успешной записи и проверки конфликта. 
Что происходит при отмене выбора имени? SaveInternalAsync возвращает false, исходное действие не 
продолжается и правки остаются в памяти. 
Как учитывается кириллица? Файл декодируется поддерживаемой Unicode -кодировкой; исходная 
кодировка запоминается для записи. Windows-1251 автоматически не определяется. 
Почему поиск видит несохранённое слово? Для текущего документа берётся буфер ViewModel, а не только 
файл на диске. 
Поиск использует регулярные выражения? Нет, IndexOf выполняет буквальное сравнение. 
Перекрывающиеся совпадения не включаются. 
Почему дерево и поиск могут показать разные файлы? У построения дерева есть бюджет и глубина; поиск 
обходит папку отдельно и ограничивает число совпадений, а не тем же бюджетом дерева.  
Почему экспорт не снимает звёздочку? Он записывает HTML -представление, а не текущий исходный .md. 
savedText при экспорте не меняется. 
Можно ли запускать HTML -код из Markdown? Интерпретация встроенного HTML отключена в Pipeline. 
Ссылки и экспорт имеют отдельные ограничения; это не среда выполнения произвольных скриптов.  
Что требуется улучшить в производительности? Полный повторный разбор и перестроение элементов могут 
быть дорогими. Можно исследовать частичное обновление и ограничение сложности, измерив реальное 
время. 
Самопроверка 
Без подсказки проследи один путь: Ctrl+S → SaveCommand → RunAsync → SaveInternalAsync → WriteAsync → 
временный файл → проверка отпечатка → замена → savedText → PropertyChanged → исчезновение звёздочки. Если 
понимаешь, зачем нужен каждый шаг, можно ответить на большинство вопросов о сохранении.
