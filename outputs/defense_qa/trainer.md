# Как устроен тренажёр набора текста
## Задача приложения и основной сценарий
Тренажёр даёт образец текста, принимает ввод пользователя, сравнивает его с образцом и показывает время, скорость, точность и ошибки. После завершения попытка попадает в историю. Пользователь может поменять размер текста, скрыть подсказку-клавиатуру и включить сравнение с учётом регистра.
Здесь заранее подготовлены десять текстов: семь русских «Текст 1» — «Текст 7» и три английских «Text 8» — «Text 10». В текущем интерфейсе нет создания собственных текстов. Каталог встроен в AppDataStore.CreateDefaultTexts, а не загружается из внешней базы данных.
Последовательность пользователя: выбрать текст → при необходимости настроить приложение и нажать «Применить» → нажать «Начать» → перепечатать образец → посмотреть итог → открыть вкладку «Статистика». «Сброс» прекращает текущую попытку без добавления результата. «Заново» запускает попытку сначала.

## Карта файлов и зависимостей
Решение называется TypingTrainerApp.slnx. Внутри три проекта. TypingTrainer — исполняемое приложение с окнами; TypingTrainer.Core — логика и данные без зависимости от Avalonia; TypingTrainer.Tests — автоматические проверки. Такая граница позволяет проверять формулы отдельно от окна.

Зависимость направлена от окна к Core. TypingSession не знает, какого цвета кнопка и как называется TextBox. Главное окно передаёт сессии строку, получает статистику и решает, как её показать. AppDataStore отдельно занимается чтением и записью данных.
## Фактическая архитектура
Для этого приложения корректное описание — событийный интерфейс с code-behind и вынесенным ядром. Главный управляющий код находится в MainWindow.axaml.cs. Полноценного отдельного ViewModel для окна нет. В разметке есть отдельные Binding для элементов списков, но они не превращают весь проект в MVVM.
Движение данных: пользователь → InputBox.TextChanged → MainWindow.OnInputChanged → TypingSession.UpdateInput → TypingSession.GetStatistics → обновление надписей и цвета. При завершении подключается AppDataStore.SaveStatistics, который записывает результат на диск.
Плюс такого решения — прямой и понятный путь от кнопки к действию. Минус — MainWindow выполняет много обязанностей, и при росте приложения его сложнее сопровождать. Возможное развитие — вынести состояние и команды в ViewModel, сохранив TypingSession и AppDataStore. Это предложение по развитию, а не уже реализованная часть.
## Три класса с данными
WordDictionary хранит Id, Name, Words и Text. Id — идентификатор Guid; Name — имя в списке; Text — полный образец. Words содержит разбиение на слова, но основная проверка набора использует Text. Название WordDictionary сохранилось, хотя фактически пользователь выбирает готовый текст, а не словарь для случайной генерации.
TrainerSettings хранит FontSize, ShowKeyboard и CaseSensitive. По умолчанию размер 16, клавиатура видна, регистр не учитывается. TypingSessionStats хранит дату, название текста, количество введённых и правильных символов, ошибки, секунды, точность и скорость.
В TypingSessionStats свойство WordsPerMinute хранит скорость в правильно набранных знаках в минуту. Это историческое имя поля JSON, сохранённое ради совместимости. Свойство CharactersPerMinute возвращает то же значение и помечено JsonIgnore, чтобы не создавать второе поле в JSON. На защите говори «знаки в минуту». Формулы слов в минуту здесь нет.
## Как создаётся главное окно
Конструктор без параметров MainWindow() вызывает другой конструктор и передаёт new AppDataStore(). Конструктор с AppDataStore нужен в том числе тестам: они могут подставить хранилище во временной папке, не трогая настоящую историю пользователя.
Далее InitializeComponent создаёт элементы из AXAML. Окно читает настройки и статистику, загружает список текстов, выбирает первый и назначает обработчики. Например, StartButton.Click связан с StartSession, InputBox.TextChanged — с OnInputChanged. Таймер Tick вызывает UpdateMetrics каждые 250 миллисекунд.
Поля с подчёркиванием — внутренние данные окна. _store — хранилище; _session — текущая попытка; _timer — периодическое обновление экрана; _keys — соответствие символов изображениям клавиш; _statistics — история в памяти; _settings — применённые настройки. Это имена, выбранные разработчиком, а не особые команды C#.
## Что происходит при нажатии Начать
StartSession проверяет, что в списке выбран WordDictionary. Затем очищает поле ввода и вызывает _session.Start(text, _settings.CaseSensitive). В сессии сохраняются образец и его название, обнуляется ввод, запоминается момент старта и устанавливается IsActive = true.
После этого окно разрешает редактирование InputBox, блокирует смену текста и регистра, меняет кнопку на «Заново», запускает таймер, перерисовывает образец и устанавливает фокус в поле ввода. Отсчёт начинается именно после нажатия «Начать», а не после первой буквы. Если задуматься перед вводом, это время повлияет на скорость.
Флаг _updatingInput временно поднимается при очистке поля программой. Изменение Text вызывает TextChanged даже тогда, когда текст изменил код. Без защитного флага собственное обновление окна могло бы попасть в обработку пользовательского ввода.
## Проверка каждого изменения текста
Событие TextChanged передаёт управление OnInputChanged. Метод сразу выходит, если идёт внутреннее обновление или сессия не активна. В остальных случаях он передаёт всё текущее содержимое поля в UpdateInput, перерисовывает образец и пересчитывает показатели.
```csharp
public bool UpdateInput(string input)
{
    if (!IsActive) return false;
    Input = input;
    if (Input.Length < Target.Length) return false;
    _finishedElapsed = Elapsed;
    IsActive = false;
    IsComplete = true;
    return true;
}
```
Это реальный метод TypingSession. Первая проверка запрещает обновлять уже завершённую попытку. Input = input сохраняет текущую строку. Пока она короче образца, результат false. Как только длина достигает длины образца или превышает её, время фиксируется и метод один раз возвращает true.
True здесь означает «именно сейчас произошёл переход к завершению», а не «текст набран без ошибок». Поэтому неверно набранный текст тоже завершает попытку. Повторный вызов уже вернёт false: IsActive выключен. Это предотвращает повторное добавление результата в историю.
После завершения поле становится только для чтения. Ошибку в последнем символе уже нельзя исправить в этой попытке: длина достигнута, результат зафиксирован. Можно начать заново. До завершения Backspace и исправления допускаются.
## Сравнение символов без сложных слов
Сравнение позиционное: первый введённый символ сравнивается с первым символом образца, второй — со вторым и так далее. При CaseSensitive = true используется обычное равенство char. При false оба символа преобразуются через char.ToUpperInvariant, и уже затем сравниваются.
```csharp
public bool Matches(char left, char right) => CaseSensitive
    ? left == right
    : char.ToUpperInvariant(left) == char.ToUpperInvariant(right);
```
Если регистр учитывается, «А» и «а» различаются. Если нет — считаются совпадением. Это простое посимвольное сравнение, а не лингвистический анализ слов. Пробелы и пунктуация тоже занимают позиции и должны совпадать.
Если в начале пропустить одну букву, последующие символы могут оказаться на неверных позициях и дать много ошибок. Алгоритм не ищет минимальное количество вставок и удалений, как редакционное расстояние Левенштейна. Такой выбор упрощает проверку и делает связь с ожидаемой следующей клавишей очевидной.
## Формулы которые нужно уметь объяснить
Пусть N — длина текущего ввода, C — число совпадений по позициям, T — прошедшие секунды. Тогда ошибки E = N − C. Точность A = C × 100 / N, а при N = 0 принимается 100%. Скорость V = C × 60 / max(T, 1). Единица скорости — правильно набранные знаки в минуту.
```csharp
var correct = 0;
for (var i = 0; i < Math.Min(Input.Length, Target.Length); i++)
    if (Matches(Input[i], Target[i])) correct++;
```
Это часть GetStatistics. Math.Min берёт меньшую длину, чтобы не выйти за границы одной из строк. Счётчик correct увеличивается только при совпадении. Все лишние введённые символы остаются в Input.Length, но не добавляют correct, поэтому считаются ошибками.
В выражениях 100d и 60d буква d задаёт double, чтобы расчёт был дробным. Math.Max(seconds, 1) заменяет слишком маленькое время одной секундой и предотвращает деление на ноль. Поэтому результат за половину секунды считается с нижней границей знаменателя в одну секунду.
Пример 1. Образец «котик», введено «ко», прошло 10 секунд. N = 2, C = 2, E = 0, A = 100%, V = 2 × 60 / 10 = 12 зн/мин. Остальные три ещё не введённых символа не считаются ошибками.
Пример 2. Образец «кот», введено «кит», прошло 6 секунд. N = 3, C = 2, E = 1, A ≈ 66,7%, V = 20 зн/мин. Длина достигнута, поэтому попытка завершится с одной ошибкой.
Пример 3. Образец «abcd», введено «ax». Одна ошибка и 50% точности. Пользователь нажал Backspace: осталось «a», теперь ноль ошибок и 100%. Ошибки отражают текущее содержимое, а не полную историю неправильных нажатий. Исправленная опечатка исчезает из счётчика, хотя потраченное время остаётся.
Пример 4. Образец «abc», одним изменением введено «abcx». N = 4, C = 3, E = 1, A = 75%. Избыточный символ учитывается, а попытка завершается. Вставка из буфера специально не запрещена, поэтому приложение не является защищённым экзаменационным измерителем скорости.
## Время и таймер выполняют разные задачи
TypingSession использует TimeProvider и временные метки GetTimestamp/GetElapsedTime для длительности. Когда попытка заканчивается, длительность записывается в _finishedElapsed. В дальнейшем она не растёт. Для даты результата используется локальная дата из источника времени.
DispatcherTimer с интервалом 250 мс нужен для обновления надписей на экране. Приложение не прибавляет 0,25 к длительности на каждом тике. Это различие полезно: задержка перерисовки не должна сама по себе менять источник измерения времени.
TimeProvider можно передать снаружи. В тестах есть свой Clock: проверка вручную «переводит» его на 10 или 30 секунд, не заставляя человека ждать. Это внедрение зависимости через конструктор. Отдельный контейнер внедрения зависимостей здесь не нужен.
## Подсветка текста и клавиатуры
RenderTarget создаёт отдельный Run для каждого символа образца. Run — фрагмент текста со своим оформлением. Правильно введённые символы становятся зелёными, неверные — красными. Следующий ожидаемый символ выделяется синим и подчёркивается. После вычисления расположения текста окно прокручивает образец к текущей позиции.
BuildKeyboard строит ряды элементов Border с подписями. _keys хранит связь между символом и соответствующим Border. HighlightNextKey берёт Target[Input.Length] и окрашивает нужную клавишу. Для заглавной буквы при учёте регистра подсвечивается Shift; в русской подсказке Shift также используется для запятой.
Это визуальная подсказка, а не экранная клавиатура: на Border не назначены обработчики, которые вводят букву по щелчку. Раскладка подсказки выбирается по названию текста, начинающемуся с «Text». Приложение не переключает раскладку самой операционной системы. Соответствие клавиш упрощено и не является полным определением всех раскладок.
## Настройки и история на диске
AppDataStore использует папку LocalApplicationData/TypingTrainer. В Windows её удобно открыть через %LOCALAPPDATA%\TypingTrainer. Там settings.json содержит настройки, statistics.json — массив результатов. При недоступном пустом системном пути предусмотрен запасной корень рядом с приложением. Сервер и СУБД для этой задачи не применяются.
JSON — текстовая запись объектов: имена свойств и их значения. Сериализация превращает объект C# в JSON, десериализация восстанавливает объект из JSON. System.Text.Json выполняет эти преобразования. WriteIndented = true добавляет отступы для удобного чтения человеком.
При сохранении сначала создаётся уникальный временный файл рядом с целевым. Затем File.Move с overwrite: true заменяет целевой файл подготовленным содержимым. finally удаляет оставшийся временный файл. Это уменьшает риск оставить обрезанный файл при ошибке записи. Здесь нет полноценной транзакционной базы или гарантии сохранности при любых аппаратных сбоях.
Если JSON синтаксически повреждён, загрузка возвращает значение по умолчанию. Размер шрифта ограничивается диапазоном 10–30 и проверяется на допустимое конечное число. Ошибки доступа и обычные ошибки файлов окно показывает в StatusText. В текущем коде нет полной проверки всех полей чужого JSON: файл истории предполагается созданным приложением.
История при сохранении сортируется по дате и ограничивается 500 результатами. На экране есть количество попыток, лучшая скорость и средняя точность по попыткам. Average здесь даёт обычное арифметическое среднее процентов, а не точность по сумме всех набранных символов.
«Применить» сначала сохраняет настройки и только после успешной записи обновляет используемый объект настроек. Во время активной попытки изменение режима регистра заблокировано. Очистка статистики требует отдельного подтверждения; память очищается после успешной записи пустой истории.
## Notebook для анализа
Файл typing-trainer-notebook.ipynb — отдельный документ с пояснениями и выполняемыми ячейками C#. Он читает statistics.json, выводит количество попыток, лучшую скорость, среднюю точность, сумму ошибок и группирует результаты по текстам. GroupBy объединяет попытки с одинаковым названием текста.
Кнопка «Открыть notebook» передаёт файл программе, назначенной в системе для его открытия. Она не встраивает среду исполнения C# в окно тренажёра. Для работы по инструкции notebook нужен VS Code с Polyglot Notebooks и ядром C#. Эти дополнительные инструменты понадобятся только для notebook, а не для основной тренировки.
Для демонстрации сначала заверши хотя бы одну попытку, затем открой notebook и выполняй ячейки сверху вниз. Если результатов нет, он сообщает об этом. В его коде имя WordsPerMinute также трактуется как знаки в минуту.

## Что реально проверено
11 сентября 2026 года выполнен существующий набор TypingTrainer.Tests: 15 пройденных тестовых случаев, 0 ошибок, 0 пропусков. Использованы имеющиеся исходники. Тесты не доказывают отсутствие всех дефектов и не заменяют репетицию на компьютере защиты.
CoreTests проверяет, что невведённые символы не являются ошибками; регистр работает для русского и английского; Backspace пересчитывает текущие ошибки; завершение происходит один раз; время после завершения не растёт; лишние символы считаются ошибками; каталог содержит нужные десять текстов; данные переживают повторную загрузку; история ограничена; C#-ячейки notebook компилируются и выполняются в тестовой проверке.
WindowTests через Avalonia.Headless проверяет выбор текста, ввод, завершение, повторное чтение результата, настройки, подтверждение очистки, прокрутку и размеры 1240 × 800 и 1000 × 700. Headless означает тестовую платформу для управления интерфейсом без обычного ручного сеанса. Это проверка окна, а не только математических функций.
Тест устроен по схеме «подготовить → выполнить → проверить». Например: создать сессию с тестовыми часами → ввести «abc» через 10 секунд → Assert.Equal проверяет 18 зн/мин и зафиксированное время. [Fact] обозначает отдельный тест, [Theory] — тест с наборами параметров InlineData.
## Как запустить из исходников
В TypingTrainer.csproj указаны net9.0 и Avalonia 12.1.2. Это версии проекта, а не утверждение о самых новых выпусках. Для сборки нужны подходящий .NET SDK и доступные NuGet-пакеты. Команды ниже выполняются из корня папки с TypingTrainerApp.slnx.
```text
dotnet restore TypingTrainerApp.slnx
dotnet run --project TypingTrainer/TypingTrainer.csproj
dotnet test TypingTrainer.Tests/TypingTrainer.Tests.csproj
```
restore получает зависимости; run собирает при необходимости и запускает приложение; test запускает проверки. Для готовой сборки под Windows x64 можно выполнить следующую команду. Это рецепт упаковки, а не заявление о проверке каждого возможного компьютера.
```text
dotnet publish TypingTrainer/TypingTrainer.csproj -c Release -r win-x64 --self-contained true -o outputs/trainer-publish
```
Для переноса копируют всю папку публикации. notebook включён в правила копирования проекта. ## Ограничения и возможное развитие
Нельзя заявлять, что приложение считает каждое ошибочное нажатие за всю попытку, проверяет слова по смыслу или автоматически переключает раскладку. Оно сравнивает текущую строку по позициям и выдаёт подсказку. Счётчик char подходит для обычных встроенных текстов, но не равен числу видимых символов во всех языках.
Завершение по длине позволяет закончить с ошибками и блокирует исправления после достижения длины. Вставка текста не запрещена. Каталог фиксированный. Нет пользователей, облачной синхронизации, базы SQL и многопользовательского рейтинга. Сохранение локальное, шифрование истории отдельно не реализовано.
Разумные направления развития: режим завершения только после полного совпадения; отдельный счётчик всех ошибочных нажатий; редактор собственных текстов; более точная модель клавиатуры; графики прогресса; выделение ViewModel. Перед изменением режима подсчёта нужно определить, какие результаты в старой истории останутся сопоставимыми.

## Возможные вопросы и короткие ответы
Почему C# и Avalonia? C# даёт строгие типы, классы и библиотеку .NET; Avalonia позволяет описать окно разметкой и управлять им из C#. В данном проекте используется настольный жизненный цикл.
Где точка входа? Program.Main. Затем запускаются App и MainWindow. Разметка сама по себе не является первой выполняемой функцией.
Это MVVM? У тренажёра нет отдельной ViewModel. Есть code-behind окна и отдельно вынесенная логика Core. Я могу показать эту границу по файлам.
Зачем Core? Чтобы расчёты, данные и сохранение можно было использовать и тестировать отдельно от интерфейса.
Когда начинается и заканчивается измерение? После «Начать» и при достижении длины образца. Источник времени — TimeProvider; экран обновляет DispatcherTimer.
Почему скорость не слова в минуту? Формула использует правильные символы без деления на длину слова. WordsPerMinute — старое имя JSON-поля, а интерфейс показывает знаки в минуту.
Почему точность в начале 100%? Так определён случай пустого ввода, чтобы не делить на ноль. Это не означает, что весь образец уже набран.
Почему ошибка исчезает после Backspace? Статистика пересчитывается по текущей строке. События ошибочных нажатий отдельно не накапливаются.
Можно ли закончить с ошибками? Да. Завершение проверяет длину, а правильность отражается в статистике. Это нужно различать.
Почему нельзя изменить регистр посередине? Тогда одна попытка оценивалась бы по разным правилам. На время попытки настройка заблокирована.
Как избегаете двойного результата? UpdateInput возвращает true только в момент перехода к завершению, после чего IsActive становится false.
Как хранятся результаты? Массив объектов сериализуется в statistics.json в локальной папке данных. Сохраняются до 500 последних результатов.
Что будет при ошибке сохранения? Окно показывает сообщение. Результат может оставаться в текущем списке в памяти, но нельзя считать его гарантированно записанным на диск.
Как тестировать время без ожидания? Передать тестовый TimeProvider, вручную сдвигать его метку и проверять формулу.
Можно ли обмануть измерение вставкой? Да, запрета вставки нет. Это учебный тренажёр, а не система контроля экзамена.
Какова сложность сравнения? Один расчёт проходит до min(N, M) символов, то есть линейно по длине. Перерисовка строит символы образца заново; для длинных текстов потребовалась бы оптимизация.
