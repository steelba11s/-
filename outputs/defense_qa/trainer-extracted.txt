1 C sharp и платформа dot NET с нуля 
Язык платформа и интерфейс 
C# читается «си шарп». Это язык, на котором мы описываем действия программы: прочитать текст, сравнить 
символы, обработать нажатие кнопки, сохранить файл. Код в файле .cs — обычный текст с правилами 
записи. Компьютеру нужно перевести его в выполняемую форму. 
.NET читается «дот нет». Это платформа: среда выполнения и большой набор готовых средств для работы 
со строками, файлами, временем и коллекциями. C# — язык инструкций, .NET — средства для их 
выполнения. Avalonia — библиотека для построения окон и элементов интерфейса поверх .NET. Это три 
связанные, но разные вещи. 
Представь мастерскую. C# — язык, на котором написано задание мастеру. .NET — оборудование и общие 
инструменты. Avalonia — набор деталей для панели управления: окна, кнопки, поля ввода. Проект 
приложения соединяет всё это и добавляет собственные правила работы. 
SDK — набор для разработчика. В нём есть инструменты сборки, компилятор и средства запуска. Runtime 
— среда выполнения готового приложения. Для изменения и сборки нужен SDK. У готовой самостоятельной 
сборки необходимые компоненты .NET могут лежать рядом с приложением. 
NuGet — система получения библиотек. PackageReference в .csproj указывает имя и версию готового пакета. 
ProjectReference связывает проекты внутри решения. Например, приложение использует классы своего Core 
через ProjectReference. Это не копирование текста исходников вручную. 
Как исходники становятся работающей программой 
Обычная последовательность такая: исходники C# и разметка Avalonia → сборка проекта → файлы приложения 
→ запуск среды .NET → создание окна → ожидание действий пользователя. В обычной сборке C# сначала получается 
промежуточный код IL; среда выполнения может преобразовывать его в машинный код через JIT. Для 
объяснения этих проектов достаточно знать этот путь; отдельная AOT-сборка здесь не показана в 
настройках проектов. 
Программа с окном не читает весь код сверху вниз заново после каждого клика. При запуске она создаёт 
объекты и подписывает обработчики на события. Затем работает цикл обработки событий: нажали кнопку 
— вызван соответствующий метод; изменили текст — вызван другой метод. 
Файлы .csproj описывают отдельные проекты. Решение .slnx объединяет несколько проектов для удобной 
работы. Каталог bin содержит результаты сборки, obj — промежуточные файлы. Править поведение 
приложения следует в исходниках, а не в сгенерированных файлах этих каталогов. 
Переменная и тип данных 
Переменная — именованное место для значения. Тип отвечает на вопрос «какие значения здесь допустимы 
и какие операции с ними можно выполнять». Имя отвечает на вопрос «зачем это значение понадобилось». 
int errors = 2; 
double accuracy = 97.5; 
bool isActive = true; 
string text = "Привет"; 
char letter = 'П';

int хранит целое число; double — число с дробной частью; bool — true или false; string — строку; char — одну 
кодовую единицу UTF-16. В обычном русском и английском тексте отдельная буква обычно занимает один 
char. Однако эмодзи и некоторые сложные символы могут занимать несколько единиц: String.Length не 
является универсальным счётчиком видимых знаков. 
Знак = присваивает значение. Знак == сравнивает два значения. Поэтому errors = 2 означает «записать 2», 
а errors == 2 — «проверить, равно ли значение двум». Точка с запятой завершает многие инструкции. Строки 
пишутся в двойных кавычках, отдельные char — в одинарных. 
var count = 10; 
var caption = "Готово"; 
var не означает «любой тип». Компилятор выводит тип из правой части: count будет int, caption — string. 
После этого нельзя просто записать строку в count. Такой вывод типа сокращает запись, сохраняя проверку 
типов. 
Условия циклы и индексы 
if (errors == 0) 
{ 
    return "Без ошибок"; 
} 
return "Есть ошибки"; 
Это учебный фрагмент тела метода, возвращающего string. if означает «если». Условие в круглых скобках 
должно дать bool. Фигурные скобки объединяют инструкции. return возвращает результат и сразу 
прекращает текущий вызов метода. В методе void можно написать просто return, чтобы выйти без значения. 
for (var i = 0; i < text.Length; i++) 
{ 
    var symbol = text[i]; 
} 
for повторяет действия. i = 0 — старт; i < text.Length — условие продолжения; i++ — увеличение на единицу 
после прохода. Индексы начинаются с нуля: в строке «кот» text[0] — «к», text[1] — «о», text[2] — «т». 
Обращение за пределы строки вызывает ошибку. foreach перебирает готовые элементы коллекции без 
ручного управления индексом. 
Частые операторы: != — не равно; !flag — противоположное логическое значение; && — одновременно 
выполнены оба условия; || — выполнено хотя бы одно. В выражении a && b правая часть не вычисляется, 
если a уже false. Тернарная запись condition ? yes : no выбирает одно из двух значений.

экземпляр, а конструктор задаёт его начальное состояние.

Коллекции и LINQ 
List<T> — изменяемый список элементов типа T. List<TypingSessionStats> хранит результаты попыток. 
Dictionary<TKey, TValue> сопоставляет ключу значение: Dictionary<char, Border> позволяет найти 
изображение клавиши по символу. Здесь Dictionary — структура данных C#, а WordDictionary — собственный 
класс приложения, несмотря на похожие названия. 
IReadOnlyList<T> предоставляет чтение списка через данный интерфейс. Queue<T> — очередь: первый 
добавленный элемент извлекается первым. Она используется при обходе папок. Запись [] в подходящем 
контексте создаёт пустую коллекцию. Угловые скобки задают параметр типа; это называется обобщением, 
или generics. 
LINQ — набор операций над последовательностями. Where отбирает элементы, Select преобразует каждый 
элемент, OrderByDescending сортирует по убыванию, Take оставляет первые N, ToList материализует 
результат в список. Max находит максимум, Average — среднее, GroupBy собирает элементы в группы. 
statistics.OrderByDescending(item => item.Date) 
          .Take(500) 
          .ToList(); 
Это цепочка из тренажёра. Сначала самые новые результаты оказываются впереди, затем сохраняются 
только первые 500, затем получается отдельный список. item => item.Date — лямбда: маленькая функция 
«для данного элемента взять его дату». => может обозначать лямбду или краткое тело члена класса; смысл 
определяется контекстом. 
Пустое значение и короткие записи 
null означает отсутствие объекта или значения ссылки. Пустая строка "" существует и имеет длину ноль; null 
означает, что строки нет. string? показывает, что отсутствие допустимо. Настройка Nullable в .csproj 
помогает компилятору предупреждать об опасных обращениях. 
InputBox.Text ?? "" читается «взять Text, а если там null, использовать пустую строку». Выражение 
document?.Path читает Path только при наличии document, иначе даёт null. Знак ! после выражения, 
например Inlines!, подавляет предупреждение компилятора о null, но не создаёт объект и не защищает во 
время выполнения. 
is проверяет тип или шаблон. is not WordDictionary text означает «если значение не удалось распознать как 
WordDictionary и получить переменную text». switch выбирает ветку по значению или типу. nameof(IsDirty) 
даёт строку с именем члена; при переименовании инструменты могут обновить ссылку безопаснее, чем

События асинхронность и освобождение ресурсов

дополнительно даёт строковый результат. async сам по себе не создаёт отдельный поток. Task.Run обычно

Что описывает AXAML 
Avalonia — средство создания графического интерфейса. Файл .axaml использует синтаксис XML для 
описания дерева элементов. Это декларативная запись: мы говорим, какие элементы нужны и как они 
размещены. Код .axaml.cs описывает связанные с окном действия. Их связывает x:Class, а загрузка 
разметки выполняется при InitializeComponent. 
<Button x:Name="StartButton" 
        Content="Начать" /> 
Button — кнопка. x:Name — имя для обращения из C#. Content — содержимое кнопки. Запись /> закрывает 
элемент без вложенных элементов. xmlns объявляет пространство имён XML: оно помогает понять, из какой 
библиотеки пришёл тип. URL в xmlns не означает, что приложение загружает разметку с сайта при каждом 
запуске. 
Window — окно; Grid — сетка; StackPanel размещает элементы последовательно; TextBlock показывает 
текст; TextBox принимает ввод; Button выполняет действие; ComboBox предлагает выбор; CheckBox хранит 
состояние флажка; ScrollViewer даёт прокрутку. Border добавляет фон, рамку и внутренние отступы.

Как работает размещение 
<Grid ColumnDefinitions="*,340"> 
    <TextBlock Text="Рабочая область" /> 
    <TextBlock Grid.Column="1" Text="Настройки" /> 
</Grid> 
Учебный пример повторяет принцип тренажёра: справа фиксированная ширина 340, слева оставшееся 
место. * означает долю свободного пространства, Auto — размер по содержимому, число — фиксированный 
размер в логических единицах интерфейса. Столбцы и строки нумеруются с нуля. Поэтому Grid.Column="1" 
означает второй столбец. 
Margin — внешний отступ, Padding — внутренний отступ между границей и содержимым. IsVisible скрывает 
или показывает элемент; IsEnabled разрешает или блокирует взаимодействие; IsReadOnly у TextBox 
запрещает редактирование. TextWrapping="Wrap" переносит длинные строки. Минимальные размеры окна

Как создаётся главное окно 
Конструктор без параметров MainWindow() вызывает другой конструктор и передаёт new AppDataStore(). 
Конструктор с AppDataStore нужен в том числе тестам: они могут подставить хранилище во временной 
папке, не трогая настоящую историю пользователя. 
Далее InitializeComponent создаёт элементы из AXAML. Окно читает настройки и статистику, загружает 
список текстов, выбирает первый и назначает обработчики. Например, StartButton.Click связан с 
StartSession, InputBox.TextChanged — с OnInputChanged. Таймер Tick вызывает UpdateMetrics каждые 250 
миллисекунд. 
Поля с подчёркиванием — внутренние данные окна. _store — хранилище; _session — текущая попытка; _timer 
— периодическое обновление экрана; _keys — соответствие символов изображениям клавиш; _statistics — 
история в памяти; _settings — применённые настройки. Это имена, выбранные разработчиком, а не особые 
команды C#. 
Что происходит при нажатии Начать 
StartSession проверяет, что в списке выбран WordDictionary. Затем очищает поле ввода и вызывает 
_session.Start(text, _settings.CaseSensitive). В сессии сохраняются образец и его название, обнуляется ввод, 
запоминается момент старта и устанавливается IsActive = true. 
После этого окно разрешает редактирование InputBox, блокирует смену текста и регистра, меняет кнопку 
на «Заново», запускает таймер, перерисовывает образец и устанавливает фокус в поле ввода. Отсчёт 
начинается именно после нажатия «Начать», а не после первой буквы. Если задуматься перед вводом, это 
время повлияет на скорость. 
Флаг _updatingInput временно поднимается при очистке поля программой. Изменение Text вызывает 
TextChanged даже тогда, когда текст изменил код. Без защитного флага собственное обновление окна могло 
бы попасть в обработку пользовательского ввода.

public bool UpdateInput(string input) 
{ 
    if (!IsActive) return false; 
    Input = input; 
    if (Input.Length < Target.Length) return false; 
    _finishedElapsed = Elapsed; 
    IsActive = false; 
    IsComplete = true; 
    return true; 
} 
Это реальный метод TypingSession. Первая проверка запрещает обновлять уже завершённую попытку. Input 
= input сохраняет текущую строку. Пока она короче образца, результат false. Как только длина достигает 
длины образца или превышает её, время фиксируется и метод один раз возвращает true. 
True здесь означает «именно сейчас произошёл переход к завершению», а не «текст набран без ошибок». 
Поэтому неверно набранный текст тоже завершает попытку. Повторный вызов уже вернёт false: IsActive 
выключен. Это предотвращает повторное добавление результата в историю. 
После завершения поле становится только для чтения. Ошибку в последнем символе уже нельзя исправить 
в этой попытке: длина достигнута, результат зафиксирован. Можно начать заново. До завершения 
Backspace и исправления допускаются. 
Сравнение символов без сложных слов 
Сравнение позиционное: первый введённый символ сравнивается с первым символом образца, второй — 
со вторым и так далее. При CaseSensitive = true используется обычное равенство char. При false оба символа 
преобразуются через char.ToUpperInvariant, и уже затем сравниваются. 
public bool Matches(char left, char right) => CaseSensitive 
    ? left == right 
    : char.ToUpperInvariant(left) == char.ToUpperInvariant(right); 
Если регистр учитывается, «А» и «а» различаются. Если нет — считаются совпадением. Это простое 
посимвольное сравнение, а не лингвистический анализ слов. Пробелы и пунктуация тоже занимают позиции 
и должны совпадать. 
Если в начале пропустить одну букву, последующие символы могут оказаться на неверных позициях и дать 
много ошибок. Алгоритм не ищет минимальное количество вставок и удалений, как редакционное 
расстояние Левенштейна. Такой выбор упрощает проверку и делает связь с ожидаемой следующей 
клавишей очевидной. 
Формулы которые нужно уметь объяснить 
Пусть N — длина текущего ввода, C — число совпадений по позициям, T — прошедшие секунды. Тогда 
ошибки E = N − C. Точность A = C × 100 / N, а при N = 0 принимается 100%. Скорость V = C × 60 / max(T, 1). 
Единица скорости — правильно набранные знаки в минуту. 
var correct = 0; 
for (var i = 0; i < Math.Min(Input.Length, Target.Length); i++) 
    if (Matches(Input[i], Target[i])) correct++; 
Это часть GetStatistics. Math.Min берёт меньшую длину, чтобы не выйти за границы одной из строк. Счётчик 
correct увеличивается только при совпадении. Все лишние введённые символы остаются в Input.Length, но 
не добавляют correct, поэтому считаются ошибками.

В выражениях 100d и 60d буква d задаёт double, чтобы расчёт был дробным. Math.Max(seconds, 1) заменяет 
слишком маленькое время одной секундой и предотвращает деление на ноль. Поэтому результат за 
половину секунды считается с нижней границей знаменателя в одну секунду. 
Пример 1. Образец «котик», введено «ко», прошло 10 секунд. N = 2, C = 2, E = 0, A = 100%, V = 2 × 60 / 10 = 
12 зн/мин. Остальные три ещё не введённых символа не считаются ошибками. 
Пример 2. Образец «кот», введено «кит», прошло 6 секунд. N = 3, C = 2, E = 1, A ≈ 66,7%, V = 20 зн/мин. Длина 
достигнута, поэтому попытка завершится с одной ошибкой. 
Пример 3. Образец «abcd», введено «ax». Одна ошибка и 50% точности. Пользователь нажал Backspace: 
осталось «a», теперь ноль ошибок и 100%. Ошибки отражают текущее содержимое, а не полную историю 
неправильных нажатий. Исправленная опечатка исчезает из счётчика, хотя потраченное время остаётся. 
Пример 4. Образец «abc», одним изменением введено «abcx». N = 4, C = 3, E = 1, A = 75%. Избыточный 
символ учитывается, а попытка завершается. Вставка из буфера специально не запрещена, поэтому 
приложение не является защищённым экзаменационным измерителем скорости. 
Время и таймер выполняют разные задачи 
TypingSession использует TimeProvider и временные метки GetTimestamp/GetElapsedTime для длительности. 
Когда попытка заканчивается, длительность записывается в _finishedElapsed. В дальнейшем она не растёт. 
Для даты результата используется локальная дата из источника времени. 
DispatcherTimer с интервалом 250 мс нужен для обновления надписей на экране. Приложение не прибавляет 
0,25 к длительности на каждом тике. Это различие полезно: задержка перерисовки не должна сама по себе 
менять источник измерения времени. 
TimeProvider можно передать снаружи. В тестах есть свой Clock: проверка вручную «переводит» его на 10 
или 30 секунд, не заставляя человека ждать. Это внедрение зависимости через конструктор. Отдельный 
контейнер внедрения зависимостей здесь не нужен. 
Подсветка текста и клавиатуры 
RenderTarget создаёт отдельный Run для каждого символа образца. Run — фрагмент текста со своим 
оформлением. Правильно введённые символы становятся зелёными, неверные — красными. Следующий 
ожидаемый символ выделяется синим и подчёркивается. После вычисления расположения текста окно 
прокручивает образец к текущей позиции. 
BuildKeyboard строит ряды элементов Border с подписями. _keys хранит связь между символом и 
соответствующим Border. HighlightNextKey берёт Target[Input.Length] и окрашивает нужную клавишу. Для 
заглавной буквы при учёте регистра подсвечивается Shift; в русской подсказке Shift также используется для 
запятой. 
Это визуальная подсказка, а не экранная клавиатура: на Border не назначены обработчики, которые вводят 
букву по щелчку. Раскладка подсказки выбирается по названию текста, начинающемуся с «Text». 
Приложение не переключает раскладку самой операционной системы. Соответствие клавиш упрощено и не 
является полным определением всех раскладок.

Настройки и история на диске 
AppDataStore использует папку LocalApplicationData/TypingTrainer. В Windows её удобно открыть через 
%LOCALAPPDATA%\TypingTrainer. Там settings.json содержит настройки, statistics.json — массив 
результатов. При недоступном пустом системном пути предусмотрен запасной корень рядом с 
приложением. Сервер и СУБД для этой задачи не применяются. 
JSON — текстовая запись объектов: имена свойств и их значения. Сериализация превращает объект C# в 
JSON, десериализация восстанавливает объект из JSON. System.Text.Json выполняет эти преобразования. 
WriteIndented = true добавляет отступы для удобного чтения человеком. 
При сохранении сначала создаётся уникальный временный файл рядом с целевым. Затем File.Move с 
overwrite: true заменяет целевой файл подготовленным содержимым. finally удаляет оставшийся временный 
файл. Это уменьшает риск оставить обрезанный файл при ошибке записи. Здесь нет полноценной 
транзакционной базы или гарантии сохранности при любых аппаратных сбоях. 
Если JSON синтаксически повреждён, загрузка возвращает значение по умолчанию. Размер шрифта 
ограничивается диапазоном 10–30 и проверяется на допустимое конечное число. Ошибки доступа и 
обычные ошибки файлов окно показывает в StatusText. В текущем коде нет полной проверки всех полей 
чужого JSON: файл истории предполагается созданным приложением. 
История при сохранении сортируется по дате и ограничивается 500 результатами. На экране есть 
количество попыток, лучшая скорость и средняя точность по попыткам. Average здесь даёт обычное 
арифметическое среднее процентов, а не точность по сумме всех набранных символов. 
«Применить» сначала сохраняет настройки и только после успешной записи обновляет используемый 
объект настроек. Во время активной попытки изменение режима регистра заблокировано. Очистка 
статистики требует отдельного подтверждения; память очищается после успешной записи пустой истории.

Файл typing-trainer-notebook.ipynb — отдельный документ с пояснениями и выполняемыми ячейками C#. Он 
читает statistics.json, выводит количество попыток, лучшую скорость, среднюю точность, сумму ошибок и 
группирует результаты по текстам. GroupBy объединяет попытки с одинаковым названием текста. 
Кнопка «Открыть notebook» передаёт файл программе, назначенной в системе для его открытия. Она не 
встраивает среду исполнения C# в окно тренажёра. Для работы по инструкции notebook нужен VS Code с 
Polyglot Notebooks и ядром C#. Эти дополнительные инструменты понадобятся только для notebook, а не 
для основной тренировки. 
Для демонстрации сначала заверши хотя бы одну попытку, затем открой notebook и выполняй ячейки сверху 
вниз. Если результатов нет, он сообщает об этом. В его коде имя WordsPerMinute также трактуется как знаки 
в минуту.

Как запустить из исходников

dotnet restore TypingTrainerApp.slnx

dotnet publish TypingTrainer/TypingTrainer.csproj -c Release -r win-x64 --self-contained true -o 
outputs/trainer-publish

Ограничения и возможное развитие 
Нельзя заявлять, что приложение считает каждое ошибочное нажатие за всю попытку, проверяет слова по 
смыслу или автоматически переключает раскладку. Оно сравнивает текущую строку по позициям и выдаёт

Тренажёр набора текста  |  15 
подсказку. Счётчик char подходит для обычных встроенных текстов, но не равен числу видимых символов 
во всех языках. 
Завершение по длине позволяет закончить с ошибками и блокирует исправления после достижения длины. 
Вставка текста не запрещена. Каталог фиксированный. Нет пользователей, облачной синхронизации, базы 
SQL и многопользовательского рейтинга. Сохранение локальное, шифрование истории отдельно не 
реализовано. 
Разумные направления развития: режим завершения только после полного совпадения; отдельный счётчик 
всех ошибочных нажатий; редактор собственных текстов; более точная модель клавиатуры; графики 
прогресса; выделение ViewModel. Перед изменением режима подсчёта нужно определить, какие результаты 
в старой истории останутся сопоставимыми.

Приложение разделено на три проекта. TypingTrainer содержит окно и обработчики событий.

ViewModel у тренажёра нет.

Возможные вопросы и короткие ответы 
Почему C# и Avalonia? C# даёт строгие типы, классы и библиотеку .NET; Avalonia позволяет описать окно 
разметкой и управлять им из C#. В данном проекте используется настольный жизненный цикл. 
Где точка входа? Program.Main. Затем запускаются App и MainWindow. Разметка сама по себе не является 
первой выполняемой функцией. 
Это MVVM? У тренажёра нет отдельной ViewModel. Есть code-behind окна и отдельно вынесенная логика 
Core. Я могу показать эту границу по файлам. 
Зачем Core? Чтобы расчёты, данные и сохранение можно было использовать и тестировать отдельно от 
интерфейса. 
Когда начинается и заканчивается измерение? После «Начать» и при достижении длины образца. Источник 
времени — TimeProvider; экран обновляет DispatcherTimer. 
Почему скорость не слова в минуту? Формула использует правильные символы без деления на длину слова. 
WordsPerMinute — старое имя JSON-поля, а интерфейс показывает знаки в минуту. 
Почему точность в начале 100%? Так определён случай пустого ввода, чтобы не делить на ноль. Это не 
означает, что весь образец уже набран. 
Почему ошибка исчезает после Backspace? Статистика пересчитывается по текущей строке. События 
ошибочных нажатий отдельно не накапливаются. 
Можно ли закончить с ошибками? Да. Завершение проверяет длину, а правильность отражается в 
статистике. Это нужно различать. 
Почему нельзя изменить регистр посередине? Тогда одна попытка оценивалась бы по разным правилам. На 
время попытки настройка заблокирована. 
Как избегаете двойного результата? UpdateInput возвращает true только в момент перехода к завершению, 
после чего IsActive становится false. 
Как хранятся результаты? Массив объектов сериализуется в statistics.json в локальной папке данных. 
Сохраняются до 500 последних результатов. 
Что будет при ошибке сохранения? Окно показывает сообщение. Результат может оставаться в текущем 
списке в памяти, но нельзя считать его гарантированно записанным на диск.

Как тестировать время без ожидания? Передать тестовый TimeProvider, вручную сдвигать его метку и 
проверять формулу. 
Можно ли обмануть измерение вставкой? Да, запрета вставки нет. Это учебный тренажёр, а не система 
контроля экзамена. 
Какова сложность сравнения? Один расчёт проходит до min(N, M) символов, то есть линейно по длине. 
Перерисовка строит символы образца заново; для длинных текстов потребовалась бы оптимизация.

примере «кот» и «кит» за 6 секунд; зачем нужен JSON и тестовый Clock. Если можешь показать это в коде,
